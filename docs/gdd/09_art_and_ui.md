## 9.2 해상도와 스케일

**도트의 "픽셀 격자"와 화면 해상도를 분리한다.** 도트 그림은 낮은 해상도의 격자로 그리되,
UI·글자·이펙트는 기기의 실제 해상도로 선명하게 그린다.

### 설계 단위
- **PC**: 1920×1080 논리 px 기준.
- **모바일**: **dp(밀도 독립 픽셀)** 기준. 가로 화면 약 **915×412 dp**를 기본 기준으로 설계한다.
  - 기기 픽셀 = dp × 기기 배율 (예: 2400×1080 폰 ≈ 배율 2.6).
  - 모바일 화면을 기기 픽셀로 설계하면 글자가 실제로는 2.5배 이상 작아진다. 레이아웃·글자 크기는 반드시 dp로 정한다.
- 더 넓은 화면(20:9 폰, 21:9 모니터)은 높이를 기준으로 맞추고, 남는 가로 공간은 보드 시야와 좌우 레일에 쓴다.
- 기기의 노치·펀치홀·제스처 바 영역(Safe Area)에는 조작 요소를 두지 않는다.

### 레이어별 렌더링

| 레이어 | 해상도 | 내용 |
| :--- | :--- | :--- |
| **월드 (도트)** | 도트 격자 × 정수배 확대 | 타일, 기물, 요충지 장치 |
| **이펙트** | 기기 해상도 | 파티클, 빛 번짐, 레이저, 화면 흔들림. 색과 모양은 도트 톤에 맞춘다 |
| **UI** | 기기 해상도 | 패널, 버튼, 카드, 글자. 테두리 장식은 도트 9-slice를 정수배 확대 |

### 도트 격자 규격
- 타일 **32×32** 도트, 기물 **32×48** 도트 (쿼터뷰, 머리가 윗칸으로 16도트 겹침).
- **타일 크기는 보드 크기와 무관하게 고정**한다. 10×10 보드라고 타일을 줄이지 않는다.
- 보드 배율(도트 1개가 화면 몇 px인지)은 정수로만 쓰고, **기기 종류에 따라** 정한다.
  - **PC**: 1080p 기준 ×3 → 타일 96px. (720p ×2 · 1440p ×4 · 4K ×6)
  - **모바일**: 화면 높이 1080px 기준 ×4 → 타일 128 기기px(약 48dp), 6인치대 폰에서 약 8mm.
    손가락으로 정확히 누를 수 있는 크기(7mm 이상)를 확보하기 위해 PC보다 한 단계 크게 쓴다.
  - 기기 해상도가 기준과 다르면 위 크기에 가장 가까운 정수 배율을 고른다.
- 기물 필수 모션 (4~6프레임): `Idle`, `Lift`(선택 시 들림), `Slam`(착지), `Hit`(피격 점멸), `Shatter`(파괴).

## 9.3 보드 뷰와 카메라

타일 크기를 고정하므로 큰 보드는 화면에 다 들어가지 않을 수 있다. **보드는 카메라로 보는 공간**으로 설계한다.

### 보드가 화면에 들어가는 정도

| 보드 | PC 1920×1080 (타일 96px) | 폰 2400×1080 (타일 128px) |
| :--- | :--- | :--- |
| 6×6 | 전체 보임 | 전체 보임 |
| 8×8 | 전체 보임 | 전체 보임 (세로 거의 꽉 참) |
| 10×8 | 전체 보임 | 전체 보임 |
| 8×10 | 전체 보임 (세로 꽉 참) | 세로 약 2줄 스크롤 |
| 10×10 | 전체 보임 (세로 꽉 참) | 세로 약 2줄 스크롤 |

- 가로 화면이라 부족한 쪽은 **세로**다. 스크롤이 필요한 경우는 모바일의 10줄 보드(Act 2 엘리트 이후)뿐이고, 그 양도 2줄 정도다.

### 카메라 조작
- **이동**: 빈 칸을 끌어서 이동 (터치 드래그 · 마우스 드래그 · 휠 · 방향키/WASD).
  - 탭과 드래그는 이동 거리 임계값으로 구분한다. 기물 위에서 시작한 드래그는 이동 예약 드래그로 처리한다.
- **자동 추적**: 플레이어가 직접 움직이지 않아도 필요한 곳을 보여 준다.
  - 계획 중: 선택한 기물과 그 이동·공격 범위가 화면 안에 들어오도록 부드럽게 이동.
  - 실행 중: 순차 공격의 현재 순번 기물을 따라가며 연출 (적 턴도 동일).
  - 실행이 끝나면 계획 시작 시점의 시야로 돌아온다.
- **확대/축소**는 일반 조작으로 두지 않는다. 타일 크기를 고정하는 원칙 때문이다. 전체를 보는 기능은 아래 "전체 보기"로 분리한다.

## 9.4 전황 파악 수단

전투 화면은 **보드 중심**으로 단순하게 유지하고, 부가 정보는 필요할 때만 꺼내 본다.

1. **전체 보기**: 버튼·`Tab` 키·두 손가락 오므리기로 잠시 보드 전체를 한 화면에 축소해 보여 준다.
   - 보기 전용이다 (예약 조작 불가). 손을 떼거나 다시 누르면 원래 시야로 돌아온다.
   - 전황 천칭(5장 §5.3), 남은 기물 수, 층·군단 정보도 이 화면에서 함께 보여 준다.
2. **화면 밖 표시**: 시야 밖의 중요한 대상을 보드 가장자리 표시로 알려 준다.
   - 적 킹, 요충지, 내 예약 공격의 대상, 적 턴에 공격받는 아군.
3. **킹 HP**: 별도 패널 없이 킹 기물의 HP 바로 본다. 적 킹이 시야 밖이면 화면 밖 표시에 HP 바를 함께 붙인다.
4. **상세 정보는 꺼내 보기**: 기물·카드는 길게 누르기(모바일) 또는 마우스 올림(PC)으로 설명과 정확한 수치를 연다.
5. **인챈트 목록**: 전투 화면에 상시 표시하지 않는다. 우측 레일의 `인챈트` 버튼을 누르면 보유 인챈트 6칸(중첩·★각성·효과)이 팝업으로 뜬다.
- 미니맵은 두지 않는다. 화면 복잡도에 비해 정보가 적고, 전체 보기와 화면 밖 표시로 대체된다.
- 다음 턴 예상 사거리, 체스 좌표는 메인 보드에 표시하지 않는다. 좌표는 예약 목록에서만 보인다.

## 9.5 화면 레이아웃 (보드 중심)

| 영역 | 내용 |
| :--- | :--- |
| **상단 바** (PC만) | 층·군단 정보 · 전체 보기 · 메뉴 |
| **좌측 레일** | **액티브 카드 4장** (2×2, TCG 카드 형태) |
| **중앙 보드 뷰** | 보드 · 이동 화살표 · 순번 배지 · 공격 범위 · 예상 HP 바 · 파괴 표시 · 화면 밖 표시 · (모바일) 전체 보기 버튼 |
| **우측 레일** | 위: 턴 표시 · `인챈트` 버튼 · **예약 목록** (순번 · 기물 · 좌표 이동) · 아래(엄지 영역): AP 진공관 · `되돌리기` · `초기화` · `제출` |

### 액티브 카드 표현
- TCG 카드 비율(약 63:88). 일러스트 · 이름 · 종류 · 왼쪽 위 비용 배지.
- **지속형**: 어두운 바탕 + 황동 테두리. **소멸형**: 양피지 바탕 + 구리 테두리.
- 쿨타임 중이면 카드를 어둡게 덮고 남은 턴 수를 가운데 표시한다.

### 인챈트·강화의 표현
- HUD에 인챈트 칸을 두지 않는다. **효과를 받는 기물 자체**에 표시한다.
  - 예: 받침대 테두리 장식(중첩 단계), ★각성은 황동 태엽 링, 대장간 강화 단계는 받침대 장식으로 구분.
  - 구체적인 시각 언어는 도트 작업 단계(M6)에서 정한다.
- 정확한 효과는 기물을 길게 누르거나 마우스를 올려 확인한다.

### 예상 결과 표현 (3장 §3.6)
- 예상 피해는 숫자 대신 **HP 바**로 보여 준다: 남는 HP(진영 색) + 잃을 HP(노란색).
- 파괴될 기물에는 X 표시를 붙인다.
- 정확한 수치는 길게 누르기·마우스 올림으로 본다.

### AP
- 진공관 개수로만 보여 준다 (숫자 없음). 의미는 튜토리얼에서 설명한다.

- 예약 목록에는 공격 대상을 표시하지 않는다. 기물을 놓는 순간 보드 위에 공격 범위와 대상이 표시되기 때문이다.
- 레이아웃 목업: Design 캔버스 "Pawnisher 전투 화면 목업"의 **3안 모바일**.

### 플랫폼 우선순위
- **모바일 레이아웃을 먼저 구현한다.** 현재 레이아웃은 모바일 기준이다.
- PC는 당분간 같은 요소를 그대로 배치한다. 넓은 화면을 살린 PC 전용 레이아웃(좌우 레일 확장, 여백 활용 요소)은 장기 과제로 둔다.

## 9.6 크로스플랫폼 조작

### 입력 방식별 대응

| 동작 | 모바일 (터치) | PC (마우스·키보드) | 게임패드 (스팀 덱 등, 후순위) |
| :--- | :--- | :--- | :--- |
| 기물 선택 | 탭 | 클릭 | 커서 이동 + A |
| 이동 미리보기 | 목표 칸 탭 | 마우스 올림 | 커서 이동 |
| 이동 예약 | 같은 칸 다시 탭 / 기물에서 끌어 놓기 | 클릭 / 끌어 놓기 | A |
| 정보 보기 | 길게 누르기 | 마우스 올림 | Y |
| 카메라 이동 | 빈 칸 드래그 | 드래그 · 휠 · WASD | 오른쪽 스틱 |
| 전체 보기 | 두 손가락 오므리기 / 버튼 | `Tab` | View 버튼 |
| 카드 선택 | 슬롯 탭 | 클릭 · `1`~`4` | 숄더 버튼 |
| 되돌리기 / 초기화 / 제출 | 버튼 | `Z` / `R` / `Space` | B / 길게 B / Start |

- 모든 조작은 입력 장치와 무관한 "명령"(선택, 미리보기, 예약, 취소…)으로 추상화한다. 새 입력 방식을 붙이기 쉽게 하기 위함이다.
- 마우스 올림(호버)에만 의존하는 정보는 없게 한다. 터치에는 호버가 없으므로 같은 정보를 길게 누르기로도 볼 수 있어야 한다.

### 크기 기준
- 보드 타일: 약 7mm 이상 (9.2).
- 버튼·슬롯: 약 9mm 이상 (논리 120px 내외).
- 글자: 모바일 본문 **14dp 이상**, 숫자·배지 등 짧은 표시는 12dp 이상. PC는 본문 16px 이상.

### 오조작 방지
- 이동 예약은 "미리보기 → 확정" 두 단계 (탭 두 번 또는 끌어 놓기).
- `제출`은 황동 레버를 끝까지 당기는 동작(PC는 클릭)으로, 실수로 누르기 어렵게 한다.
- 슬롯 교체: 인챈트 6칸·액티브 4칸이 가득 찬 상태에서 새로 얻으면,
  기존 슬롯이 붉은 테두리로 바뀌고 "버릴 것 1개를 선택하세요" 창이 뜬다. 포기도 선택할 수 있다.

### 접근성
- 색만으로 구분하지 않는다. 아군·적은 색(청록/진홍)과 함께 기물 받침대 모양으로도 구분한다.
- 화면 흔들림·점멸 끄기 옵션, 연출 속도 옵션(1× / 2× / 건너뛰기).

## 9.7 턴 연출 (Juice)

### 계획 단계
- 기물을 목표 칸에 올리면 **푸른 화살표**와 순번 번호표(#1, #2…)가 붙는다.
- 착지 칸 기준 공격 범위가 **붉은 크로스헤어 타일**로 맥동하고, 대상마다 예상 피해 숫자와 파괴 표시가 뜬다 (3장 §3.6).
- 앞 순번이 비켜 준 자리는 반투명 잔상으로 남아, 뒤 순번 사선이 뚫리는 것이 보인다.

### 실행 단계
1. **제출**: 황동 레버가 철컥 내려가며 증기음.
2. **일괄 이동**: 예약 기물이 0.25초 동안 동시에 잔상을 남기며 착지(쿵).
3. **순차 공격**: 순번 번호표가 빛나며 차례로 공격.
   - 피격 시 0.06초 히트스톱 · 화면 흔들림 · 흰색 점멸 · 데미지 숫자.
   - 파괴 시 파편이 튀고 타일이 비워진 뒤, 다음 순번의 사선 이펙트가 그 빈자리를 뚫고 지나간다.
   - 순번이 올라갈수록 타격음 피치가 올라간다.

### 적 턴
- 적의 예약 화살표와 순번을 잠깐 보여 준 뒤 같은 연출로 실행한다 (4장 §4.5).
- 연출 속도 옵션을 따른다 (9.6).

## 9.8 사운드

- 기물 착지음, 레버 증기음, 순차 타격음(순번마다 피치 상승), 파괴음, ★각성 발동음.
- BGM은 고딕 오르간·현악 + 기계음 질감.

## 9.9 에셋 분담

- **코드로 직접 구현** (개발 측): 기물 도트 스프라이트와 모션, 보드 타일, 요충지 장치, 이펙트, 개발용 플레이스홀더 전반.
- **외부 제작** (기획 측, 다른 AI 생성·외주): 버튼, 패널 프레임, 카드 일러스트, 아이콘 등 UI 에셋.
  - 외부 에셋의 규격(도트 크기, 9-slice 여백, 상태별 이미지)은 구현 단계에서 **에셋 요청 명세서**로 따로 정리해 전달한다.
- 상용 에셋 팩은 사용하지 않는다.
