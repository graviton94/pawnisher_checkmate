## 10.2 아키텍처 원칙

1. **규칙 엔진은 순수 TypeScript**다. Phaser·DOM에 의존하지 않는다.
   - 같은 엔진을 화면, AI, 테스트, 세이브 복원이 함께 쓴다.
2. **결정론**: 모든 무작위는 시드 RNG에서 나온다. 같은 상태 + 같은 입력 = 같은 결과.
   - 세이브·복원, 리플레이, 버그 재현, 3지선다 세이브스커밍 방지에 쓰인다.
3. **상태는 직렬화 가능**한 순수 데이터다. 턴 중간 어디서든 저장·복원할 수 있다.
4. **진영 중립**: 엔진은 1P/2P를 구분하지 않는다. 플레이어(UI)와 AI는 같은 `Plan`을 제출한다 (D-002).
5. **데이터 주도**: 기물 스탯, 인챈트, 카드, 군단, 층 구성은 `src/data/`에 둔다. 밸런스 조정에 코드 수정이 필요 없게 한다.
6. **AI는 Web Worker**에서 돈다 (4장 §4.6).

## 10.3 디렉터리 구조 (예정)

```
src/
  engine/    규칙 엔진: 보드, 행마, 공격 판정, 턴 진행, 요충지 (순수 TS)
  ai/        계획 탐색, 평가 함수, Web Worker 진입점
  data/      기물·인챈트·카드·군단·층 데이터
  run/       등반 맵, 보상, 상점, 대장간, 경제, 메타 진행
  view/      Phaser 씬, 보드 렌더러, 연출
  ui/        HTML 오버레이 화면
  platform/  세이브 저장소, 플랫폼별 연동 (Capacitor / Electron)
tests/       엔진·AI 테스트
```

## 10.4 로드맵
