# 20장. 시뮬레이션 실험실 — 봇으로 재미 · 밸런스의 대리 지표를 뽑는다 (D-456)

> 상태: **1단계 적용(2026-11-13)**. 사용자가 시니어 제안(경량 병렬 시뮬레이션 4단계)을 가져왔다 — 「사람이 직접 테스트하지 않아도 봇을 제대로 설계해 시뮬레이션을 돌리는 기법」. 이 장은 그 제안을 우리 코드에 맞춘 설계와 진행이다.
> 원칙: 봇 지표는 **사람의 대리값**이다. 숫자가 「재미있다」를 증명하지는 않지만, 「어디가 무너졌나 · 어떤 시드를 사람이 봐야 하나」를 정확히 짚는다. 사람 플레이 기록은 이 지표의 눈금을 맞추는 데 쓴다.

## 2. 지표 — 정의와 우리 게임에 맞춘 기준

| 지표 | 측정 | 기준 (사람 기록으로 눈금을 다시 맞춘다) |
|---|---|---|
| 아슬아슬함 | 반장 · 검문을 이긴 뒤 남은 분대 체력 비율 | 중앙 30 ~ 50% · 15 ~ 30% 구간이 넉넉히 · 70% 이상은 적게 |
| 막힘 | 태엽이 남고 낼 카드가 있는데 턴을 끝낸 비율(봇) | 15% 아래 |
| 결정적 한 턴 | 이긴 대국에서 우리 피해의 40% 이상이 한 턴에 몰린 비율 | 공정 열기(D-454) 때문에 뒤 턴이 자연히 크다 — 30 ~ 60%를 「쌓고 터뜨리는」 정상 범위로 본다 |
| 성장 기울기 | 막별 턴당 준 피해 · 이긴 대국 턴 수 | 이긴 대국 턴 수가 막마다 크게 늘지 않을 것(3막 ≤ 6턴) |
| 경제 · 압축 | 종막 직전 쥔 나사 · 덱에 남은 시작 카드 | 나사가 많이 남으면 쓸 곳이 없다는 뜻 |
| 픽률 × 보유 시 완주 | 제시 · 선택 기록과 그 출하 완주 | 표본이 크지 않으면 잡음 — 판정은 아래 「짝 비교 힘 값」을 우선 |
| 짝 비교 힘 값 | 같은 시드로 아이템을 쥐여 준 출하 vs 안 준 출하의 「이긴 대국 수」 차 · 완주율 차 | 표준오차 2배 밖으로 크게 + = 너프 후보, − = 함정(들면 진다) |

픽률은 봇의 가치표가 정한 값이라 「사람이 고를까」가 아니라 「가치표가 맞나」를 본다. 아이템 자체의 힘은 짝 비교가 정확하다(봇이 고르든 말든 쥐여 주고 잰다).

## 3. 단계

1. **(완료, D-456)** 지표 수집 — 대국마다 턴별 준 피해 · 한 방 · 이긴 뒤 체력, 출하마다 제시 · 선택 · 경제. 페르소나 risky · hoarder, 두뇌 봇 온도. 보고서 `tools/simlab-report.mjs`, 짝 비교 `tools/simlab-items.mjs`.
2. **이상 시드 다시 보기**: 보고서가 「1막에서 한 턴에 셋 잃음」 같은 극단 시드 번호를 뽑고, `?debug&seed=`로 같은 출하를 화면에서 재생한다(사람이 눈으로 확인).
3. **속도**: 수읽기의 `JSON` 복제를 구조적 복제(필요한 칸만)로 바꿔 두뇌 봇을 5 ~ 10배 빠르게 — 하룻밤 수만 판.
4. **눈금 맞추기**: 테스터 기록(telemetry)의 대국 길이 · 손실 · 남은 체력을 같은 표로 뽑아, 봇 온도 · 페르소나 비율을 사람 분포에 맞춘다. 그 뒤로는 패치마다 같은 보고서로 회귀를 본다.

## 4. 쓰는 법

```bash
npm run climb -- --styles search,greedy --asc 0,2 --n 200 --jobs 6 --personas standard,risky,hoarder --out sim/lab.json
node tools/simlab-report.mjs sim/lab.json --min 20 > docs/reports/<날짜>-simlab.md
node tools/simlab-items.mjs --kind part --n 60 --jobs 6
node tools/simlab-items.mjs --kind card --n 60 --jobs 6
```
