# 12장. 한 판의 피로도 & 턴 피드백

> 상태: 💬 검토 중 (D-031). 용어는 `docs/world.md` 용어집을 따른다 (이 장은 이해를 위해 지금 코드의 이름을 괄호로 같이 쓴다).
> 근거: 사용자 피드백 "8×8 이상·기물이 많으면 한 판이 부담스럽다", "내 턴에 한 것의 피드백이 확실히 오지 않는다".

## 12.1 진단 — 측정과 실제 화면

### 판 길이 (AI 대 AI, 같은 덱, 단계 2, `sim/fatigue.sim.ts`, 12판)

| 보드 · 덱 | 양측 합 턴 (내 턴) | 턴당 예약 | 피해 없는 턴 | 최장 무피해 연속 |
| :--- | :-: | :-: | :-: | :-: |
| 8×8 · 11 대 11 | 17 (9) | 2.1 | 6% | 1 |
| **8×8 · 16 대 16** | **43 (22)** | **1.5** | **41%** | **51** |
| 10×8 · 16 대 16 | 20 (10) | 2.2 | 0% | 0 |
| **8×10 · 16 대 16** | **39 (20)** | **1.4** | **37%** | **56** |

- 판 길이가 둘로 갈린다: 보통은 20~27턴인데, **풀 덱 8×8·8×10의 약 1/3이 70~84턴짜리 정체판**이 된다. 50턴 넘게 아무도 때리지 않다가 15라운드 붕괴·서든데스가 와서야 끝난다.
- 원인: 좁은 폭에 16기가 서면 폰 전열이 서로 막히고, 앞으로 나가는 쪽이 먼저 맞는 구조라 **양쪽 다 기다리는 게 최선**이 된다. 같은 덱이라도 **폭이 10이면 측면이 열려 20턴에 끝난다.**
- 사람은 턴마다 내 기물 16기 + 적 16기의 위협을 훑어야 한다. 내 턴 22번 × 30~60초 = **한 판 10~20분**. 목표(8장 §8.1: 중후반 4~6분)의 2~3배다.
- 제출 → 내 실행 → 적 생각 → 적 실행: 한 턴에 **약 7.6초** 기다린다 (실측, 4수 예약 기준). 속도 조절·건너뛰기가 없다.

### 피드백 (실제 모바일 화면 915×412, `production/qa/evidence/2026-10-30-feedback-diag-*.png`)

| 관찰 | 문제 |
| :--- | :--- |
| 실행 중 피해 숫자가 작고(약 12px) 회색 칸 위 황갈색, 0.65초 만에 사라짐 | 무엇이 몇 피해를 줬는지 놓친다 |
| 공격자 → 대상 연결이 짧은 붉은 선 한 번 | 여러 기물이 맞으면 누가 누구를 쳤는지 안 보인다 |
| 순번 표시 `#4`가 작은 글자로 잠깐 | 지금 몇 번째 수인지 따라가기 어렵다 |
| **턴이 끝나면 아무 흔적도 없다** | 적 룩이 어디서 왔는지, 내 폰이 언제 맞았는지 알 수 없다 (실행 후 화면) |
| HP는 기물 아래 얇은 선 | 깎인 양이 잘 안 보인다 |
| 결과 요약·전투 기록·다시 보기·소리 없음 | 테이블 게임인데 "방금 무슨 일이 있었나"를 되짚을 방법이 없다 |

## 12.2 피로도 개선

목표: **중후반 일반 대국 내 턴 8~12번, 4~6분.** 엘리트·군주 대국은 더 길어도 된다.

| # | 개선 | 내용 | 검증 |
| :-: | :--- | :--- | :--- |
| F1 | **정체 압박** (Gambonanza 크럼블) | 양 진영 모두 피해를 주지 못한 라운드가 **2번 연속**되면 그 라운드부터 판 붕락(붕괴)을 시작한다. 피해가 나면 정체 카운트는 0으로. 붉은 금 예고 + 레일에 "정체 1/2" 표시 | 정체판(최장 무피해 ≥ 10)이 0이 되고, 정상판 길이는 그대로 |
| F2 | **넓은 보드 우선** | Act 2 일반 대국 8×8 → **10×8**. Act 3도 8×10보다 10×8 비중↑. 8×8은 덱이 작은 Act 1 (11기까지는 17턴) | 위 표의 10×8 수치 |
| F3 | **군단은 수보다 질** | 일반 군단 상한 12기. 더 강하게는 개량(대장간 강화)·특수 부품(접사)으로. 정예·군주만 13기 이상 | 훑어야 할 적 기물 수 ↓ |
| F4 | **가호 붕괴** | 전력(5장 §5.3 스코어)이 상대의 25% 아래로 떨어진 진영의 킹은 체크 보호를 잃는다 → 이미 이긴 판의 "킹 쫓기" 단축. D-022 조정이라 **사용자 확인 필요** | 결판 직전 구간 턴 수 |
| F5 | **실행 속도** | 1× / 2× / 4× + 「적 턴은 결과만」(애니메이션 없이 흔적만 남김). 화면 탭 = 남은 연출 즉시 끝. 적 생각 중 표시 | 적 턴 1×에서 3초 이내 |
| F6 | **훑기 보조** (정답은 안 알려 줌) | 선택 전부터 ① 이번 턴 **칠 수 있는 내 기물**에 작은 칼 표식 ② 다음 적 턴에 **처치될 수 있는 내 기물**에 ☠ (위협 지도와 같은 공개 정보, D-028 #5) | "어디부터 볼까"가 줄어드는지 사용자 테스트 |
| F7 | **판 길이 예산** | 시뮬 KPI: 일반 대국 양측 합 턴 Act 1 ≤ 16 · Act 2 ≤ 20 · Act 3 ≤ 24, 정체판 0% | `/balance-check`에 추가 |

- 기각: 출전 기물 고르기(매 판 덱 편성) — D-026 사용자 결정. 턴 제한·판정승 — D-014.

## 12.3 턴 피드백 설계

### 원칙
테이블 게임의 피드백은 "번쩍임"이 아니라 **인과(무엇이 → 무엇을 → 얼마나)가 보이고, 끝난 뒤에도 남는 것**이다.

| 층 | 언제 | 무엇을 | 지금 |
| :-: | :--- | :--- | :-: |
| 1. **예고** | 제출 전 | 이동·과녁·예상 HP 바·처치 금색·키워드 칩 | ✅ (칩 추가) |
| 2. **실행** | 제출 후 | 순번마다 정해진 박자로 이동 → 타격 → 결과 | 🔶 약함 |
| 3. **흔적** | 실행 후 ~ 다음 제출 | 판 위에 방금 일어난 일이 남는다 | ❌ 없음 |
| 4. **기록** | 언제든 | 턴별 기록, 다시 보기 | ❌ 없음 |

### 2. 실행 — 한 순번의 박자 (≤ 0.6초, CLAUDE.md 원칙 6)

| 박자 | 시간 | 화면 | 소리 |
| :-: | :-: | :--- | :--- |
| ① 지명 | 0.05 | 행동 기물 외 판을 살짝 어둡게, 순번 배지를 기물 위에 크게(현재의 2배) | 톡 |
| ② 이동 | 0.18 | 들림 → 미끄러짐(증기 꼬리) → 착지 눌림 + 증기 퍼프 | 쿵 |
| ③ 조준 | 0.07 | 사선 = 빛줄기가 대상까지 뻗음, 지점 = 대상 칸 과녁 깜빡 | 철컥 |
| ④ 타격 | 0.20 | 히트스톱 0.06 · 대상 흰 점멸 + 2px 밀림 · **피해 숫자 크게**(피해 비례 18~28px, 흰 글자 검은 테두리) · HP 바를 잠깐 크게 펼쳐 **깎인 구간이 노랗게 남았다가 줄어드는 잔상** | 탕 (순번마다 음 높이↑) |
| ⑤ 결과 | 0.10 | 처치 = 부품 파열(톱니·스프링 파편) + 금색 "처치", 체크 = 킹에 붉은 고리 + 종소리, 키워드 배너(포크!·돌파!) | 와장창 / 종 |

- 순번 사이 0.05초 쉼. 4수 예약 = 약 2.5초.
- **적 순번도 같은 박자**, 다만 맞는 쪽이 내 기물이므로 ④에서 내 기물 테두리를 붉게 깜빡이고 화면 흔들림을 조금 크게.
- `prefers-reduced-motion`·연출 끄기: ①②⑤ 움직임을 줄이고 흔들림을 없앤다. **흔적(3층)은 줄이지 않는다** — 정보이기 때문이다.

### 기물별 공격 연출 (사용자 피드백, 구현됨 — 코드 도트 임시판)
공격은 **기물 중심에서 그 기물의 공격 범위로 뻗는다.** 이펙트가 칸에 닿는 순간 그 칸의 피격(점멸·스파크·숫자)이 일어난다.

| 기물 | 몸짓 | 이펙트 | 박자 |
| :--- | :--- | :--- | :-: |
| 폰 | 살짝 부풀기 | 전방 대각선 두 칸을 가르는 초승달 칼날 | 0.2초 |
| 나이트 | 깡충 | 발밑 충격 고리 → L자 궤적(긴 다리 → 짧은 다리) → 착탄 별 | 0.24초 |
| 비숍 | 살짝 부풀기 | 빛 알갱이가 몸으로 응축 → 4대각선 광선, 첫 기물에서 멈춤, 깜빡이며 사라짐 | 0.3초 |
| 룩 | 들었다 쿵 | 발밑 사각 충격 → 십자 방향으로 **한 칸씩 이어지는 폭발** | 칸당 0.06초 |
| 퀸 | 살짝 부풀기 | 응축 + 고리 → 8방향 광선 | 0.27초 |
| 킹 | 들었다 쿵 | 주변 8칸으로 퍼지는 사각 충격파 | 0.2초 |
| 공통 | — | 행마에 안 맞는 추가 칸(스플래시·연쇄)은 주 타격 직후 작은 폭발 · 처치 = 톱니·스프링 파편 · 피격 = 스파크 + 큰 피해 숫자 | |

- 색: 아군 = 흰 백자 + 황동 스파크, 적 = 붉은 과열광. 모든 도형을 도트 격자(칸 = 16도트)에 맞춰 찍는다 (`src/view/pixel.ts`).
- 증거: `production/qa/evidence/2026-10-30-attack-fx-{P,N,B,R,Q,K}.png` (`tools/fx-observe.cjs`, 4배 느리게 `?fxslow`).
- 발주 시트 E(`docs/asset-order.md`)가 오면 같은 박자에 스프라이트로 갈아 끼운다.

### 3. 흔적 — 다음 제출까지 판에 남는 것

| 흔적 | 모양 | 사라지는 때 |
| :--- | :--- | :--- |
| 지난 이동 | 출발 칸 점선 테두리 + 옅은 화살표 (적 = 붉은, 아군 = 청록) | 내 다음 제출 |
| 받은 피해 | 맞은 기물 오른쪽 위 작은 칩 `−12` (이번 턴 합계) | 내 다음 제출 |
| 처치 자리 | 쓰러진 칸에 잔해 표식 (흑 = 검은 톱니, 백 = 흰 톱니) | 다음 라운드 |
| 체크 | 킹 받침에 붉은 고리 유지 | 체크가 풀릴 때 |
| 턴 요약 | 레일 위 한 줄: `내 턴: 처치 2 · 피해 47 · 체크` / `적 턴: 내 나이트 −18 · 폰 처치` | 다음 요약이 덮을 때 |

- 판정 시험: **실행이 끝난 화면 한 장만 보고** "적이 무엇을 움직여 무엇을 쳤나"를 답할 수 있어야 한다 (`/run-and-observe` 증거).

### 4. 기록 — 되짚기
- 우측 레일의 예약 목록 자리는 내 차례가 아닐 때 **전투 기록**이 된다: 턴마다 `기물 아이콘 c1→f4 ⚔ 비숍 −9 ☠`.
- 기록 한 줄을 누르면 그 턴을 **다시 보기** (결정론 — 턴 시작 상태 + 계획만 저장하면 그대로 재생된다).
- 기물을 길게 누르면 "지난 턴에 받은 피해·준 피해"도 같이 보인다.

### 소리 (최소 세트)
들림 · 착지 · 타격(순번 음 높이↑) · 처치 · 체크 종 · 제출 레버 · 위협 경고 · 승리/패배, 8종.
처음엔 코드로 만든 칩튠 효과음(작은 생성기)으로 넣고, 사용자가 원하면 교체한다 (`docs/art-assets.md`의 "조합 먼저" 원칙과 같음).

## 12.4 구현 순서 (M10 앞에 끼워 넣는다 → **M9.5**)

1. 흔적 3층 + 턴 요약 + 실행 박자 다듬기 + 속도 옵션 (F5) — 화면만 바뀜, 규칙 그대로.
2. 정체 압박 (F1) + 넓은 보드 (F2) + 군단 상한 (F3) → 시뮬로 F7 KPI 확인, D-025 곡선 재확인.
3. 훑기 보조 (F6) + 위협 지도 — M10 A3과 합친다.
4. 전투 기록·다시 보기, 효과음.
5. 가호 붕괴 (F4)는 사용자 확인 후.

- 각 단계는 `/run-and-observe`(실행 중 프레임 캡처 포함) · `/ux-review` · `npm test` · `/balance-check`.
