## 5. 튀는 값 — 원인 후보 · 사용자 판단 필요

### 5-1. 두뇌 봇 첫 출하 95% (목표 ~80%)

- 직전과 같은 값(95 → 95). 원인 후보(직전 보고 §4와 같음): 두뇌 봇은 적의 수를 실제로 돌려 보고 피하므로 적 공격 배율 · 적 AI 강화가 보통 봇만 깎는다. 버팀 · 쇳물 서약 · 태엽 상한은 사람의 지름길을 막는 장치라 봇 곡선에 거의 안 보인다.
- **사용자 판단 필요** — 사용자가 직접 첫 왕관을 해 보고 답하기로 했다. 측정 쪽에서 바꾼 것 없음.

### 5-2. 보통 봇 왕관 4 — 2막 벽

- 왕관 4에서 출하의 52%가 2막에서 끝난다(왕관 1 · 2 · 3은 17 · 19 · 31%). 완주 10%(직전 6%)는 띠 안의 움직임이지만, 끝나는 자리가 2막에 몰렸다.
- 원인 후보(검증 안 함): ① 왕관 4(승급 3)부터 휴식 · 수리에 `ASC_NUM.restMul`이 붙는데, D-503 이후 작업대 수리가 분대 전체 → 가장 다친 하나로 바뀌어 두 효과가 겹친다(1막에서 깎인 HP를 2막에서 못 채움). ② 왕관 4 2막 이형 · 특성 수. ③ 무작위 표본(100출하에서 2막 끝 52 vs 31 — 차이 21%p로 표본 오차보다는 크다).
- **사용자 판단 필요** — 높은 왕관은 사람 시험 뒤 다시 본다는 직전 결론(D-492)대로 두었다. 필요하면 다음 측정: 같은 시드로 작업대 수리만 옛 방식으로 돌린 짝 비교.

### 5-3. 보통 봇 왕관 1 · 다 열린 풀 27% (띠 35~40)

- 직전 26%와 같다. 처음 풀(첫 출하 조건)은 44%로 띠 안 — 직전 보고 §4대로 두 조건을 따로 본다. **사용자 판단 필요**(바꾼 것 없음).

## 부록 — 재현

```bash
npm run climb -- --styles greedy,random --asc 0,1,2,3 --n 100 --jobs 4 --out sim/climb-2026-11-15-gr.json
npm run climb -- --styles search --asc 0,1,2,3 --n 40 --shard 10 --jobs 4 --out sim/climb-2026-11-15-se.json
npm run climb -- --styles greedy --asc 0 --n 80 --pools starter --jobs 4
npm run climb -- --styles search --asc 0 --n 40 --pools starter --shard 10 --jobs 4
```

- 출하당 대국 수 · 교착 포함 출하 · 반장 턴은 `--out` JSON의 `b` · `lg`(대국마다 `[막, 종류, 승, 턴, …, 교착]`)에서 셌다.
- 버팀 곡선(§3)은 `simulateRun`의 대국 시작 직전에 `braceLeft` · `braceMax` 합을 찍는 한 줄을 넣은 임시 복사본으로 쟀다 — 다시 재려면 같은 한 줄을 넣고 위 시드로 돌린다.
