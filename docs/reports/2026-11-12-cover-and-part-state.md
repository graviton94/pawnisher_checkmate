# 장면 cover 통일과 UI-34 — 2026-11-12 (D-443)

사용자 선택지 중 **비율을 유지해 확대하고 잘라서 영역 전체를 채우는 방식**을 적용했다. 추가 장식 발주는 없다. 원본 PNG·팔레트·기물·아이템·프레임은 바꾸지 않았다.

## 표시 범위

프롤로그·격파·엔딩 같은 전체 화면 컷은 뷰포트를 채운다. 사건·상점·손질·왕위 선택·크레딧·막 소개는 기존 글/그림 분할을 유지하면서 그림 영역을 채운다. 반장 등장 초상도 오른쪽 그림 영역을 같은 계산으로 채운다. 일러스트 영역의 빈 양옆을 허용하지 않으며 가로/세로 배율을 다르게 적용하지 않는다.

`src/view/cover.ts`의 `fitCover`를 공통으로 사용한다. 기기 픽셀 정수 배율을 택하고 초점을 기준으로 크롭하며, 화면 회전/창 크기 변경 때 다시 계산한다. 기본 카메라는 정지, 명시된 컷 연출은 유지한다. 그림의 가장자리를 모두 보존하는 정책은 아니며, 원본 파일을 잘라 저장하는 작업도 아니다.

## UI-34

보유 부품의 턴 제한 효과11종에 상태를 연결했다. 대기는 현재 낼 수 있는 명령으로 조건이 충족되지 않는 상태, 가능은 합법 명령 중 실제 발동하는 행동이 있는 상태, 소진은 이번 턴의 실제 발동 기록이다. 기물별 제한인 공성 걸쇠는 룩별 기록과 미사용 수를 표시한다. 상시 효과에 소진 표식을 만들지 않는다.

`partStatuses`는 판을 복제해 실제 `playCard`를 실행한 뒤 발동 기록을 읽는다. 효과 공식을 UI에 재구현하지 않으며 원래 판·RNG·저장에는 손대지 않는다. 되감기와 새 턴에 표시도 실제 기록을 따라 복구된다. 상태 아이콘뿐 아니라 상세에 한국어 이름과 진행을 표시한다. 연출/적 차례에는 가능 상태를 예측하지 않는다.

97×5=485건은 같은 컷 렌더러를 통한 **자동 기하 검사**다. 모든 원화의 미학/초점을485회 사람이 합격시켰다는 뜻이 아니다. 실제 사건·장소·반장·선택·크레딧은 전 화면 audit에 별도로 포함한다.

UI-34의 실제 터치 검수는 미리보기에서 방열판15→3, 실행 후3, 되감기 후15 및 실제 발동 기록 복구, 세 빌드 선택과 첫막 진행, 저장 격리를 확인한다. 작은 모바일에서 부품84종의 상세/복합 설명 다음 쪽/고정 높이 교체 화면/6·8칸을 다시 검사했으며 상태 설명도 글·화면 경계 안에 있다. 기존 본편3장/별도 도전/약속·저장 복귀·빈 동료 캠페인 흐름도 통과했다.

단위 테스트36파일308개 통과. `fitCover`20케이스, 실제 부품 상태·실행·복구 및 원판 불변을 포함한다. 빌드와 타입 검사 통과. 기존4000회 JSON 쓰기 용량 테스트는 동일한 상한 경계의 전/후를 저장소 초기값+5회 쓰기로 검사해 과부하 시 타임아웃을 제거했다. 게임 기록 저장 방식은 바꾸지 않았다.

## 검수에서 고친 추가 문제

- 초반 카드 안내의 `kblink`가 버튼 자체를 숨겨 터치가 누락될 수 있었다. 카드는 계속 보이고 테두리만 강조하도록 바꾸고 애니메이션 네 시점의 가시성을 확인했다.
- 빠르게 다른 기물 정보창을 열면 퇴장 중인 이전 검사판이 잠시 남을 수 있었다. 새 판을 열 때 이전 퇴장 판을 제거하고 중첩 회귀 검사를 추가했다. PC 연락표에서는 장소/팝업 위에 전투 검사판이 남는 별도 문제도 찾았다. 장면·대국 전환 때 정보판을 즉시 정리하고 팝업/컷/비활성 보드의 전투 입력을 차단한다. 네 규격의12개 장면 전환에서 검사판 제거·재개방 방지·배경 판 불변을 확인한다.
- 실제 길게 누름 검사는 고정550ms 뒤 무조건 손을 떼는 대신 미리보기 발생을 확인하고 손을 떼도록 했다. CPU 부하로 입력 처리 시점이 밀린 경우를 게임의 성공/실패로 오인하지 않는다.

화면·기능 변경 범위의 판정은 APPROVED다. 실기기 열·배터리·손가락 촉감·모든 개별 색의 대비 계측은 NOT ASSESSED이며 자동 검사를 통과했다는 이유로 합격으로 바꾸지 않는다. 그래픽 정본의 실제 화면과 로컬 HTML은 갱신했고 외부 웹 아티팩트를 게시하지 않았다. 설치 파일 결과는 후속 통합 검수/빌드 기록에 남긴다.
