# 원본에서 실제 픽셀화한 배경 검증 — D-423

사용자 요청은 도구의 존재 확인이 아니라 **개발 측이 직접 수령 원본에 변환 도구를 실행하는지** 점검하는 것이다. 원본을 다시 읽어 픽셀화하고 현재 게임용 PNG와 비교했다.

## 실제 실행과 결과

`tools/qa/scene-pixel-audit.py`로 원본이 대응되는 배경·화면 그림 **15장**을 재생성했다. 크기와 RGBA 전체 픽셀을 비교해 **15장 모두 현재 게임 파일과 일치**했다. PNG 압축 방식이나 메타데이터가 아닌 실제 픽셀을 비교했다. 원본·게임 파일·변환 결과의 해시와 격자값은 [JSON 기록](2026-11-11-scene-pixel-audit.json)에 있다.

| 범위 | 재생성한 게임 파일 |
|---|---|
| 타이틀 | `prologue-00` |
| 공정 배경 | `act-0` ~ `act-4` |
| 장소 배경 | `bg-shop`, `bg-forge`, `bg-event`, `bg-reward` |
| 진입 화면 | `entry-battle`, `entry-check` |
| 결과·크레딧 | `end-clear`, `end-fail`, `credits-bg` |

첫 자동 격자 검사에서는 14장 중 13장이 일치했다. `credits-bg`는 자동값으로 만든 결과가 387×192여서 현재 293×146과 달랐다. D-349의 수동 격자 **5.9px**를 적용하자 전 픽셀이 일치했다. 이는 변환 누락이 아니라 기록에만 남아 있던 수동 설정이었다. 재반입 시에도 이 값이 적용되도록 `tools/pixel/scene_recipe.py`에 보존하고, 실제 반입과 검증 도구가 같은 설정을 읽게 했다. 이후 타이틀도 확인해 최종 15/15 일치했다.

고물상과 크레딧은 `tools/scene-import.py` 명령도 임시 작업 폴더에서 직접 실행했다. **원본 보관 사본의 해시**와 **산출 PNG의 전 픽셀**이 각각 원본·현재 게임 파일과 일치했다. 검증 산출물은 임시 폴더에 두었으며, 동일한 기존 게임 파일을 불필요하게 교체하지 않았다.

## 다시 실행

```bash
python3 -I tools/qa/scene-pixel-audit.py --output-dir /tmp/scene-pixel-audit
```

`report.json`과 재생성 PNG는 지정한 폴더에 생긴다. 차이·오류가 있으면 종료 코드 1을 반환한다. 특정 그림만 확인하려면 `--scene bg-shop`처럼 지정한다. 자동 복원은 격자 검출→칸별 대표색→논리 픽셀 PNG 생성이며, 장면의 색은 유지한다. 아이콘·UI는 각 반입 도구에서 별도로 팔레트와 알파를 맞춘다.

반입 완료는 **원본 보관→도구 실제 실행→변환 결과 확인→게임 연결**까지다. `image-rendering: pixelated` 설정이나 해상도 확인만으로 완료라 하지 않는다. 본 검증 범위는 위 15장이고, 저장소의 모든 초상·사건 컷까지 재생성한 것은 아니다.
