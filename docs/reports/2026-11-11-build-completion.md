# UI 마감 뒤 세 빌드의 기능·획득·기록 연결 — D-431

UI 마감은 D-430의 손패 경첩 차콜 변경으로 끝냈다. 이어 기존 리뉴얼판을 감사하고 **혼성·나이트·룩의 입문→완성 조합→획득 경로→동료 손실/기록**을 연결했다. 이는 세 운영의 기능 검증 완료이며, 전체 게임의 재미·승률·반복 피로에 대한 최종 판정은 아니다.

## 감사에서 확인하고 고친 것

| 코드에서 확인한 문제 | 적용 |
|---|---|
| 황금 폭주 코일/공성 망치를 등급 추첨 없이 시작 꾸러미에서 직접 지급 | 두 황금 부품 제거, 충돌 입문을 모루 장갑으로 대체. 꾸러미 전체에 황금 부품 제외 검사 |
| 편자 꾸러미가 재행동 카드만 두 장 지급 | 첫 처치용 기습+후속 피의 질주로 변경 |
| 처치 드로우 집게가 범용 엔진인데 일반 등급 | 희귀로 변경. 상점95나사, 일반 첫 상점 보조 보장에서는 제외 |
| 같은 축의 첫 상점 보조 공급이 첫 플레이에만 적용, 혼성 null 축은 누락 | 매 출하 첫 상점의 일반 보조품 한 개. 기능군 상성으로 혼성도 연결. 유료이며 정비·제거와 예산 경쟁 |
| 시작 물건 이후 보상이 운영의 다른 역할과 이어진다는 근거가 부족 | 보상 첫 칸만 기능 상성3:1. 등급·해금·기물·중복 조건을 먼저 적용. 해당 등급이 없어 전체 풀로 대체할 때는 상성 가중치를 끈다 |
| 혼성에는 환급이 있지만 다음 단계의 일격이 없고, 고참에게는 보호 역할이 없음 | 황금 분대 인장과 희귀 맞댄 철판 구현 |
| 준 피해 원장이 `h.damage`를 더해 방열판·과잉 피해를 전투 이력으로 계산 | 사건 순서의 실제 HP 감소만 누적. 중복 격파도 한 번만 집계 |
| 생존 대국과 승리가 구별되지 않음 | `wins`: 승리 대국에서 살아남은 횟수. 기존 `battles`와 분리 |
| 상점 방문 횟수가 저장되지 않음 | `shopsSeen` 저장/복원. 새 출하에서0으로 시작 |

현재 실제 모듈 집계는 **기본 명령92·보상 명령86·부품84·꾸러미13**이다. [전체 콘텐츠·공급 목록](2026-11-11-build-inventory.json), [현행 부품 CSV](../gdd/18-current-parts.csv). 재집계: `node tools/build-audit.mjs <결과.json>`.

## 서로 다른 세 운영

| 운영 | 실제로 연결한 행동 | 남는 대가·실패 조건 |
|---|---|---|
| 혼성 | 폰 공격→나이트 공격→톱니 태엽 환급→룩의 인장 첫 타격 ×1.8 | 세 영구 유형·명령·자리가 필요. 인장은 황금이며 세 번째 유형의 첫 직접 대상만 강화. 임시 폰·승격으로 유형 늘리기·반사·빈 이동은 준비가 아님 |
| 나이트 | 기습 처치→편자 태엽/집게 드로우→피의 질주로 다음 처치 | 첫 처치와 다음 착지가 없으면 엔진이 멎음. 집게는 희귀, 부품 칸과 추가 카드를 모아야 함 |
| 룩 | 생존3승 고참에게 방열판 카드→이웃 룩에6 공유→2태엽 공격에 판을 소모해 첫 타격 강화 | 카드·인접 위치·고참·비싼 명령이 필요. 시연에서 룩 방열판21→9. 남은 방어를 포기하는 선택이며 자동 재생 엔진은 아님 |

분대 인장의 증폭은 미리보기와 실행에 같은 엔진 옵션을 사용한다. 관통 뒷 대상·튐·충돌에 ×1.8을 다시 곱하지 않는다. 단독 인장도 선행 유형을 기록하며, 톱니가 완성 필수품은 아니다.

맞댄 철판은 킹 외 고참이 양수 방열판 카드를 받았을 때만 발동한다. 상하좌우의 다른 영구 동료 중 HP 비율이 낮은 한 명, 동률이면 시리얼 순이다. 유효 이웃이 없으면 횟수를 쓰지 않고, 부품 전체에서 턴에 한 번이다.

## 동료의 기록과 손실

`protectedDamage`는 나눠 준 판이 **실제 적 피해를 흡수한 양**이다. 방열판 출처를 먼저 받은 순서로 소비한다. 예를 들어 일반 판2+고참의 판6에 피해3이면 고참의 공적은1이며, 피해12이면6이다. 준 양 전체를 공적으로 세지 않는다. 공성 소모·아군 충돌·자가 방어는 제외한다.

출처·기여·발동 이력은 JSON 복제와 되감기로 함께 복구된다. 승리 생존·보호 누계는 실제 동료의 Crew에 저장되며 새 영입에게 전임자의 기록을 복제하지 않는다. 옛 저장의 `battles`를 승리로 추정하지 않으므로 `wins`와 보호는 새 기록부터 쌓인다. 기존 처치·피해·생명 기록은 보존한다. 폐기 원부에도 피해·생존 승리·보호·버팀을 함께 남긴다.

기존 분대 카드 받침 아래 정보 줄에 생존 승리·보호량을 표시했다. `defied`는 실제 쓰러짐과 다르므로 카드 표시를 **버팀**으로 고쳤다. 생명을 소모해 죽음을 넘긴 횟수라는 뜻이다. 새 장비 관리 화면은 추가하지 않았다.

## 실행 검증

- 웹 빌드·35파일 **282개 테스트 통과**. `npm test -- --maxWorkers=4 --testTimeout=20000`.
- 새 전투 검사는 세 번째 유형의 첫 대상·빈 이동·동일 유형·임시 기물·관통·충돌·미리보기 일치·되감기, 고참 조건·인접/비율 선택·한 번 발동·부분 흡수·실제 보호·공성 소모/아군 충돌 제외, 두 나이트 처치의 자원/손패 연속을 확인한다.
- 저장 왕복에 방문 횟수·승리·보호 필드를 포함해 보존을 확인했다. 공급 검사는 시작 황금 우회 금지, 혼성 기능군 연결, 첫 상점 이후 제한 해제, 상성/다른 후보 공존, 동일 시드 재현을 확인한다. 공급 확률의 최종 밸런스 목표나 승률로 해석하지 않는다.
- `node tools/slice-observe.cjs builds-complete`: 실제 손패 탭→기물→목적지로 세 조합을 실행했다. 태엽0/4/5, 인장 소모, 룩 방열판21→9, 나이트 후속 처치를 검사했다. 세 줄 인장 설명·분대 기록을 열고, 첫 상점의 일반 보조품을 실제로 구매해 보유 부품에 추가되는 것까지 확인했다. 시험판은 본편 localStorage를 바꾸지 않는다.
- 기존 `builds` 시나리오: 길게 누르기 미리보기·실행·되감기·세 비교판·첫막 일반/검문/반장 전환·저장 격리 통과. 이 중 전환 검사는 종료 상태를 배치하므로 실제 첫막 승률을 측정한 것이 아니다.
- 캠페인 3장/약속/이어하기/출하/해금/도전 분리/옛 저장 회귀 검사 통과. 브라우저 오류 없음. 분대 UI audit의 TXT/ERR0. 새 수치 줄과 설명을 실제 화면으로 대조했다.

## 판정과 남은 범위

세 빌드의 기능·획득 연결은 실행 가능한 상태다. 전체9종 빌드, 최근 제안 회피, 빈 역할 보장, 길 열기 기여 원장은 이번 완료 범위에 포함하지 않는다. 적 전투 수치나 승률을 조정하지 않았다. **자동 테스트는 인간이 느끼는 재미를 증명하지 않는다.** 다음 사용자 플레이에서는 조립 전에도 선택이 재미있는지, 완성 때 체감이 큰지, 같은 고점만 반복하는지, 고참을 잃었을 때 복구가 납득되는지를 본다.

화면 변경 범위의 기록·설명·기존 구매 조작은 확인했다. 전체 게임의 접근성/노치/모든 해상도 전수 검수와 네이티브 PC 앱 화면은 이번 검사에서 NOT ASSESSED다. 그래픽 정본용 자료는 로컬 갱신했다. 기존 아이콘을 사용하며 I-14A~D의 원본 반입 대기는 유지한다. 새 발주·APK·웹 아티팩트 배포는 없다.
