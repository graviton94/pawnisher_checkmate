# 혼성·나이트·룩 첫 검증판 — D-420

2026-11-11 · 대상: 리뉴얼 본편 `src/slice/` · 자동 기능 검사와 모바일 관찰 보고. 사용자 플레이의 재미·승률 평가는 포함하지 않는다.

## 실행과 읽는 순서

1. `npm run dev` 후 게임 주소 뒤에 `?builds`를 붙인다. 개발 메뉴(`?debug&opening`)의 **빌드 시험**에서도 연다.
2. 혼성·나이트·룩 중 하나를 고른다. 같은 K/P/N/R 분대, 같은 전장·손패·덱, 핵심 부품 하나만 바뀐다. 룩 방열판 15도 세 운영에 공통이다.
3. 명령·기물을 고른 뒤 **갈 칸을 길게 누르면** 공격 후 태엽·방열판과 적 HP를 본다. 손을 떼면 실행하지 않으며, 짧게 탭하면 실행한다. 부품을 탭하면 조건을 읽는다.
4. 비교 대국이 끝나면 **첫막을 간다**로 일반전→정예전→반장 시험 동선을 둔다. 생존자·남은 HP·승격·전투 기록이 다음 대국에 이어진다. 새 시험은 다시 같은 분대로 시작한다.

첫막 시험은 기존 `battleFor(1, …)`의 적·반장·깊이 성장 규칙을 쓰는 고정 동선이다. 지도·상점·보상 선택으로 조합을 획득하는 전체 런은 별도 검증 대상이다. 시험마다 되감기 1회를 제공한다. 본편 저장·메타 진행·텔레메트리에 시험 결과를 쓰지 않는다. 시험은 새로고침 뒤 이어지지 않는다.

재료 부족·막힌 배치·동료 손실은 `?debug`의 `sliceApi.buildTrial('rook', 'missing' | 'blocked' | 'loss')`로 재현한다. `mixed`·`knight`도 같은 네 조건(`ready` 포함)을 지원한다. 일반 사용자는 우선 정상 비교판을 이용한다.

## 구현

| 항목 | 실제 동작 |
|---|---|
| 맞물린 톱니 | 입장 유형이 서로 다른 영구 분대원 둘이 적 HP/방열판에 피해를 주면 태엽 +1, 턴에 한 번. 승격·임시 폰·자동 반사로 유형을 추가하지 않는다 |
| 공성 걸쇠 | 기본 비용 2 이상인 룩 전용 이동 명령의 첫 직접 대상에 방열판 최대 12를 합산, 룩마다 턴에 한 번. 다듬어 실제 비용이 1이어도 발동한다 |
| 피해 분리 | 소모분은 배수 전에 더한다. 관통 뒷 대상·튐·충돌에 재적용하지 않는다. 공격 전 소모하므로 이후 반사는 남은 방열판에 맞는다 |
| 태엽 표시 | 상한 5에서 실제 받은 환급량만 표시한다. 상한에 막혀도 해당 부품의 턴당 기회는 소비한다 |
| 본편 공급 | 두 부품을 초기 해금 풀·기존 꾸러미·일반 부품 공급에 연결. 톱니 일반, 걸쇠 희귀. 걸쇠는 룩 보유 조건. 노출 확률·완성형 희소성 보정은 V2 |
| 기존 판정 수정 | 불법 지휘가 턴당 지휘 기회를 소비하던 순서를 바로잡았다. 미리보기 실패 뒤 상태를 남기지 않는다 |

공성 걸쇠는 방열판이 0이면 기회를 소모하지 않는다. 이후 같은 턴 방열판을 받은 뒤 유효 공격하면 소모할 수 있다. 행진·기마 돌격에 실제 참여한 영구 동료의 공격은 톱니에 집계하고 자동 반사(`area` 없는 공격)는 제외한다. 영구 분대 대응은 대국 기물 ID를 사용하며 표시용 세 자리 시리얼을 식별자로 쓰지 않는다.

## 에셋과 다음 작업

사용자가 첨부한 네 그림은 대화에서 확인했다. 현재 실행 환경에는 해당 PNG 원본 경로나 다운로드 가능한 파일 ID가 전달되지 않아 원본 보관·알파·격자·32/16px 반입 검수는 수행하지 못했다. A/B는 기존 `forkGear`·`anvilPlate`를 계속 빌린다. C/D는 아직 효과·보상 풀에 등록하지 않았다. 원본 파일이 환경에 전달되면 I-14A~D를 보존하고 게임용 파생본으로 교체한다.

다음 구현 단위는 **V2 획득 경로**다. 이 검증판의 고정 지급은 획득 난도가 적절하다는 증거가 아니다. 시작 꾸러미·영입·보조 재료·고점 부품의 공급을 분리하고, 같은 재료가 너무 쉽게 완성되거나 끝내 보이지 않는 경로를 기록한다. 고참 보호와 맞댄 철판(V3), 분대 인장(V4), 대본 연결(V5)은 그 뒤의 작업이다.


## D-421 UI 전반 재점검과 기물 정보 개편

기존 자동 관찰을 전부 실행해 **75장**을 촬영했다(`915×412`, DPR 1). 전투·예고·경고·튜토리얼·지도·사건 선택/풀이/결과·보상·상점·작업대·분대·덱·영입·원부·용어·제보·설문·결과/크레딧을 포함한다. TXT·ERR·FAIL은 0건이었다. 화면 묶음으로 배치를 비교하고, 밀도가 높은 화면과 기물 창은 원본 크기로 열어 글과 테를 확인했다. 모든 런타임 조합을 촬영했다는 뜻은 아니다.

관찰 도구의 보상 시나리오가 승리 상태 없이 종료 함수를 호출해 패배 창을 찍던 문제, 상점이 옛 구매 단추를 찾던 문제를 고쳤다. 해당 두 시나리오는 현재 선택 구조로 다시 촬영했다. 이전에 같은 장면이라고 찍힌 사진을 그대로 통과 근거로 쓰지 않는다.

| 읽는 길 | 판단·처리 |
|---|---|
| 빌드 선택: 부품 그림→빌드 이름→한 줄 운영→선택 | 긴 회색 문장 단추를 그림과 두 단계 글로 바꿨다. 세 항목의 그림·이름·설명 자리가 같다. 모두 한 화면에 있고 선택창의 높이·버튼 간격을 검사한다 |
| 전투: 왼쪽 명령→중앙 착지→오른쪽 예고→턴 끝 | 상세 수치는 요구할 때만 연다. 다중 타격 예측은 두 명까지, 더 많으면 첫 대상+나머지 수로 줄여 4정보 줄 안에 둔다 |
| 기물 검사: 초상/소속·예정 행동→체력/방열판→공격/방어→특성 | 적의 짧은 탭과 길게 누르기가 모두 검사표를 연다. 기존의 HP/공격 숫자 칩을 없앴고 방어력을 추가했다. 큰 숫자는 라벨 아래 별도 줄에 놓아 붙지 않는다 |
| 보상·영입·분대·덱: 카드 이름→그림→효과→하단 선택 | 기존 카드 가족을 유지한다. 선택하지 않은 상태의 비활성 진행을 시각적으로 확인했다. 새 부품 긴 조건은 별도 정보 엿보기에서 읽는다 |
| 상점·작업대: 이름/가격→물건→현재 선택 요약→하단 진행 | 한 번에 모든 물건 설명을 펼치지 않는다. 옆 카드가 걸쳐 보이는 가로 레일은 탐색 단서이며 글자 창 자체의 넘침과 구분했다 |
| 사건: 그림/상황→대사→선택 결과→진행 | 선택 효과와 비용을 별도 줄로 유지한다. 기존 종이 결과판·선택지의 테 안에 글이 들어오는지 확인했다 |

새 검사표의 일반 적·반장·체력 `12345/18000`·방열판 87·공격 234·방어 18 사례를 **DPR 2.625 실제 터치 경로**로 확인했다. 창 경계뿐 아니라 계기 칸 안의 글자 경계도 검사한다. 일반 상태는 가볍게, 특성이 있는 반장은 아래 설명만 늘어난다. 정보창 클래스를 치수 계산 전에 적용하고 세로 여백과 방열판 배치를 정리하고 하단 단추 위로 위치를 제한했다. 큰 수·반장 특성 사례에서도 턴 종료 단추를 가리지 않는지 자동 검사한다.

전반의 시각 품질에서 남은 약점은 ‘같은 평평한 철판의 반복’, ‘능력치 칸의 재질 차이 부족’, ‘결과 장부의 흰 직사각형’이다. 각각 UI-31 검사판 외곽, UI-32 계기 칸, UI-33 장부 종이판으로 구체화했다. [발주서 25위](../asset-order-master.md#ui-polish-orders)의 상자 전체를 각각 복사하면 되며, UI-31부터 제작한다. 받은 원화가 없는 지금의 화면을 최종 아트 합격으로 보고하지 않는다.
