# 작은 상징·장부 핀 복원 — D-427

초기 반입에서 방열판·칼·방패와 장부의 황동 핀이 손상됐다. 프레임 경계와 글자만 확인하고 이 작은 도상들의 뜻과 원본 형태를 대조하지 못했다. 초기 D-426의 시각 품질 판정은 이 항목에 대해 잘못됐다.

## 원본·이전 결과·수정 결과

[확대 비교판](../../build-res/order/UI-32-33-symbol-recovery.png)은 위부터 **수령 원본 / D-426의 잘못된 결과 / D-427 수정 결과**다. 같은 원본에서 직접 추출했으며 새 그림을 생성하거나 그리지 않았다.

| 문제 | 원인 | 수정 |
|---|---|---|
| 방열판 세 줄이 두 덩어리로 뭉침 | 프레임 전체를 32×32로 줄여 상징이 5~6도트가 됨 | 세 줄을 원본에서 별도 추출해 16×16 상징으로 표시 |
| 공격의 칼자루·가드, 방어의 끝과 몸체가 소실 | 작은 도상을 프레임과 같은 격자로 샘플링 | 칼날·가드·손잡이와 방패 끝을 보존하는 독립 격자로 추출 |
| 장부 핀이 작은 얼룩이 되고 붉은색이 섞임 | 종이판과 함께 축소하고 황동 음영을 붉은 잉크와 같은 팔레트에서 선택 | 약 21.7px 윤곽에 정렬한 영역을 16×16 독립 격자로 읽어 윤곽·반사광을 보존. 황동 전용 명암 사용 |
| 상징 가장자리의 색 먼지·도형 손상 | 마스킹 밖 투명 픽셀의 RGB까지 대표색 계산에 참여 | 새 상징 추출에서 불투명 표본만 색 계산에 사용하고 원본 검은 외곽을 보존 |

프레임은 같은 원본의 빈 철 모서리를 사용하고, 상징은 **체력·공격·방어 라벨 옆과 방열판 막대 옆**에 둔다. 장부는 종이 받침과 좌우 핀을 나눠, 판이 늘어나도 핀을 줄이거나 늘이지 않는다. 하트도 같은 독립 상징 체계로 옮겼다.

황동에는 수령 원본의 짙은 갈색을 보존하는 `#4A3414`를 추가했다. 갈색을 빨강이나 구멍처럼 보이는 검정으로 바꾸지 않는다. 종이·철·붉은 상징에는 각각의 재질 색을 사용한다.

## 확인 방법

1. **시각 대조:** 원본과 이전·수정 결과를 확대해 세 줄·칼자루·방패 끝·핀의 닫힌 외곽과 명암을 확인했다. 실제 게임 크기의 스크린샷도 별도로 확인했다.
2. **도상 검사:** `python3 -I tools/qa/stat-symbols.py`가 방열판 세 줄, 연결된 칼날·가드·손잡이, 아래로 좁아지는 방패, 두 핀의 연결된 윤곽·황동 명암·붉은색 부재를 검사한다. 단순 크기·해시 검사와 구분한다.
3. **실행 확인:** 일반 기물·반장·큰 수치에서 새 상징 파일이 실제 표시되고 기기 픽셀 정수배인지 확인한다. 모바일 915×412, 작은 폰 667×375, PC 1280×720에서 글·능력·수치·턴 종료 경계를 검사한다. 장부의 양쪽 핀도 실제로 로드된 파일을 대조한다.

기본 검사판에서는 상징·라벨 위에 수치를 겹쳐 붙이지 않도록 공격·방어를 두 줄로 배치한다. 넓게 펼친 S 정보판은 기존 가로 배치를 유지해 낮은 화면의 높이를 확보한다. 글자 크기와 세 줄 능력은 유지한다.

원본 파일 네 장은 그대로다. UI-31 검사판 외곽과 S-01 그림도 바꾸지 않았다. 변환·자르기·원본 해시는 [현재 반입 명세](../../build-res/order/UI-31-33-import.json), 재생성 대조는 [현재 검증 기록](../../build-res/order/261111-verification.json)에 남긴다.
