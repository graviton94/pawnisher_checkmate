# UI · UX · FX 일관성 점검 — 같은 성격은 같은 연출로

- 범위: 본편(`index.html` → `src/slice/`) 전 화면 + 판 연출(`src/view/BoardRenderer.ts`).
- 근거: 코드 전수(`slice.css` 키프레임 88 · `style.css` 42 · `uifx.ts` · `fx3.ts` · `BoardRenderer.ts`) + 실화면 `production/qa/evidence/2026-11-02-{aud,fx3,fx3c,fx3d,title}-*.png` (915×412 · DPR 2.625).
- 결론: **연출이 세 시기(D-180 판 연출 · D-184 UI · D-189 3부)에 층층이 쌓여서, 같은 일을 하는 연출이 2~4가지 방식으로 공존한다.** 아래 표의 「통일안」대로 하나로 묶자는 제안이다. (그래픽 결정 = 사용자 몫. 승인하면 적용)

## 0. 같이 찾은 버그 (바로 고침)
- 타이틀 「시험장」 버튼이 아무 반응이 없었다 — 연결 코드가 분대 창에 잘못 들어가 있었다. 그 탓에 **분대 창을 열면 오류가 나서 「이름」 버튼이 먹통**이었다. 둘 다 고침.
- 분대 창 → 폐기 원부 → 「닫기」가 분대가 아니라 타이틀로 돌아갔다 → 분대로.
- 규칙 창 제목이 개발용 이름 「수직 조각 — 분대 + 명령 덱」 → 「규칙」.
- 「불량 폐기」 도장이 아래 문장 첫 줄을 가렸다 → 위아래 여백.

## 4. 적용 순서 (승인하면)
1. **재료**: 곡선 · 시간 · 색을 CSS 변수와 `src/data/fx.ts`에 한 벌로 — Phaser와 DOM이 같은 값을 읽는다. (화면은 그대로)
2. **함수 하나로**: `shake` · `flash` · `arcFly` · `stampIn` · `sweep` · `fold` — 같은 성격은 같은 함수를 부른다.
3. **성격별 교체**: 위 표 순서대로(선택 → 안내 → 알림 위계 → 등장/퇴장 → 숫자 → 글 → 도장 · 창 머리 → 소리).
4. **옛 것 지우기** + 화면 전수 다시 찍기 + `/ux-review`.
