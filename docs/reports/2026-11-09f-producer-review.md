## 1. 총평 — 화면을 가로지르는 문제 10

한 줄 결론: **카드 얼굴 · 장면 그림 · 타이틀은 출시 수준이다. 그 그림들을 담는 「틀」이 화면마다 다른 사람이 만든 것처럼 보인다.** 창 틀 4갈래, 창 폭 9가지, 제목 문법 5가지, 단추 자리 4가지. 플레이어는 이것을 「싸구려」로 읽는다. 슬더스 · 발라트로가 고급스러워 보이는 이유는 그림이 아니라 **모든 창이 같은 자리 · 같은 크기 · 같은 단추**라서다.

### 3.7 화면 레이아웃 두 가지 (창이 아닌 것)
**`.scr-pick` — 하나 고르기(보상 · 핵심 부품 · 영입 · 부품 · 카드 고르기)**: 창을 띄우지 않고 화면 전체가 작업대.
```

y 54 │   [받침 204×276] 16 [받침] 16 [받침] (16 [받침])            │  ← 3장 = 644, 4장 = 864
     │    카드 168×252 + 받침 아래 24px 안에 덱 영향 1줄 12px        │
y338 │                                                            │
y356 └ [건너뛴다 철 160×48]                     [고른다 황동 160×48] ┘ y404
```
합: 8 + 38 + 8 + 276 + 18 + 48 + 8 = **404 ≤ 412**. 카드 누름 = 받침 `-sel` + 「고른다」 켜짐, 같은 카드 다시 누름 = 확정. 확인 창 없음.

**`.scr-place` — 장소(고물상 · 작업대 · 결과)**: 왼쪽 장면 그림, 오른쪽 일.

## 4. 구현 순서 — 패스 5 (패스마다 한 갈래를 통째로)

원칙: 패스 하나가 끝나면 그 갈래의 **옛 선택자는 지워져 있다**. 새 규칙을 위에 덧칠하지 않는다. 각 패스 끝에 `npm test` · `node tools/artguide/ui-audit.cjs` · 915×412 촬영(`game-ui-design.md` 6장 점검표 13) · `/ux-review`.

### 패스 0 — 키트 다듬기 · 토대 (반나절)
- `tools/pixel/ui_kit_import.py`에 정렬 단계: 단추 12장 32×20 · 선택지 4장 72×24 같은 캔버스로, 눌림 = 면 1도트 아래. `scene-frame`에서 위 명패 분리. 9-slice 변 검사(가운데 행 · 열이 단색인지, 리벳 변은 `round`).
- `kit.css` 토큰 + 부품 클래스 전부, `uikit.ts` 빌더 넷. 아직 아무 화면도 바꾸지 않는다. 부품 견본 화면(`?debug` `sliceApi.kit()` 옆에 `kitSheet()`) 하나로 촬영 검수.
- 결정 필요(사용자): `--px`를 기기 정수(DPR 2.625 → 1.905px)로 바꿀지(`game-ui-design.md` 3.5). 바꾸면 모든 9-slice 테가 고르게 찍힌다.

### 패스 1 — 창 갈래 (모든 `#overlay` 창 + 확인판)
