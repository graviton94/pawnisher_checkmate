# 새 이야기와 실행 게임의 정합성 감사·수정 (D-425)

사용자는 실제 게임의 화면·문구·로직이 새 이야기와 맞지 않음을 지적했고, **서막을 포함한 본편 3장 + 이후 선택 도전**을 확정했다. 기존 코드의 승급 13과 문서의 8장은 본편 구조로 유지할 수 없었다. 현재 기준은 [실행 정본](../brief/scenario-runtime.md) 한 곳에 모았다.

## 발견한 충돌과 처리

| 기존 실행/문서 | 새 이야기와의 충돌 | 반영한 변경 |
|---|---|---|
| 실행 13단·의뢰서 8장 | 세 번의 완주로 본편을 마치는 구조와 다름 | 본편 0/1/2, 선택 도전 3~13을 별도 모드·진행으로 분리. 기존 전투 수치 재사용 |
| 같은 폰의 회귀·열세 겹 증언 | 각 장은 새 폰이고 이전 폰이 왕좌에 남음 | 세 장의 도금왕 증언과 새 상자 진입. 실제 왕위 기록·서명한 규정이 다음 폰에게 남음 |
| 거절 버튼이 떨리다 비활성화 | 마지막 선택의 유효성과 혼동 | 앞 두 장의 왼쪽은 ‘돌아본다’. 셋째 장에서는 ‘함께 나간다’가 실제 엔딩 분기 |
| 동료 상자가 용광로로 감 | 승리하면 출하한다는 전제와 배신의 의미 파괴 | 생존 동료는 실제 출하. 새 왕만 남아 ‘출하해라’고 명령 |
| 공장 정지·경고등·특수 출하 인과 | 불량인 채 함께 떠나겠다는 선택을 다른 비밀에 종속 | 공장은 계속 돌아감. 자기 몸·동료를 택한 다음 부모의 반품 제안과 아이의 환대 |
| ‘정품 판정’, ‘정품!’ 도장 | 완벽한 세트의 승인을 버리는 결말과 충돌 | ‘공정 돌파/통과’, ‘왕위 계승/함께 출하/도전 완료’로 구별 |
| 13단에서 왕관을 벗고 폰 행마로 전환 | 서사 해방을 전투 중 행마 변경에 묶음 | 해당 강제 변경과 옛 최종장 판 UI 제거. K는 끝까지 지휘 역할 |
| 고정 박차·분대원의 엔딩 대사 | 이미 폐기된 인물이 말하거나 다른 개체의 사연을 가짐 | 실제 생존자·시리얼·소원으로 약속/엔딩 생성. 전멸·사망자는 빈 자리와 원부로 처리 |
| 원수 보상으로 같은 시리얼 부활 | 영구 폐기와 패배의 죽음을 취소 | 기존 태엽의 나사 가치만 유품으로 회수. 인물 부활 제거 |
| 모든 동료의 죽음이 주인공 찬양 | 독립된 욕망보다 감화 장치로 수렴 | 합류/마지막 말에 미련·자기 길·저항을 남김. 박차를 무조건 현재 생존자로 언급하지 않음 |
| 본편과 추가 난도의 해금/기록 혼합 | 진엔딩 뒤에도 같은 타락을 반복 강제 | 본편 완료 시 기본 풀 개방. 도전 단계·난도별 시도/완주·오늘의 도전을 분리 |
| 분 단위 출하 ID | 빠른 재시도에서 과거 분대 원부가 섞일 수 있음 | 밀리초·모드·시드로 출하 ID 생성. 인물은 출하 ID+일련번호로 구별 |
| 옛 소설·성경·각본을 정본으로 안내 | 다음 작업자가 폐기된 이야기를 다시 주입 | 보관 표시와 현재 정본 링크. 의뢰서·세계·GDD·개발 규칙 동기화 |
| 옛 배신/에필로그 고정 분대 그림 | 용광로 배신·죽은 동료·검은 나이트 행렬을 시각적으로 재도입 | 새 결말에서 사용 중단. 실제 분대 대역/상자 배경, 새 손 장면 S-01 발주 |

## 코드와 플레이 기준

- [장·모드·식별](../../src/data/campaign.ts), [진행·저장 호환](../../src/slice/save.ts), [실행 각본](../../src/data/script.ts), [실제 동료 약속](../../src/data/companion-scenes.ts), [게임 연결](../../src/slice/main.ts).
- 첫 두 종이왕의 왕위 계승은 고정된 비극이다. 셋째 장은 왕의 몸/함께 출하의 실제 선택이다. 마지막에 왕이 되어도 세 장의 완주는 기록하고 기본 해금을 준다. 셋째 장을 다시 읽어 진엔딩을 볼 수 있다.
- 선택 도전은 현재 11개 난도다. 더 높은 승천 수나 새 아이템을 구현한 것으로 취급하지 않는다. 기존 난도 프로필을 재사용하며 이번 작업은 승률 조정이 아니다.
- 도전의 성공/실패는 본편을 진행시키거나 이미 본 진엔딩을 취소하지 않는다. 도전 완료는 본편 타락 컷을 재생하지 않는다.
- 옛 통계·해금·원수·진행 중 출하는 보존한다. 옛 진엔딩은 `legacyStory`로 보관한다. 모드가 없는 옛 저장은 도전으로 이어지며 새 본편은 미관람으로 남는다.
- 저장 시점은 기존처럼 지도/대국 시작이다. 약속과 장·모드는 그 저장에 함께 들어간다. 전환 컷 중 나간 경우를 새 저장 체크포인트로 추가한 것은 아니다.

## 검증

- `npm run build`: TypeScript/Vite 통과.
- `npm test`: **34개 파일 / 265개 테스트 통과**. 세 장의 순차 진행, 미래 장 건너뛰기 방지, 마지막 왕위 선택/진엔딩 재선택, 기본 해금, 도전·일일 분리, 옛 메타·진행 저장, 사망자 대사 방지, 유품, 규정, 환대의 순서, 원부 경계를 포함한다.
- 실제 터치 재현: `CHROMIUM_PATH=/usr/bin/chromium node tools/slice-observe.cjs campaign`. 모바일 **915×412 DPR 2.625**, 작은 가로 **667×375 DPR 2.625**, PC **1280×720 DPR 1**에서 본편 세 장 → 도전 진입, 약속 뒤 이어하기, 전멸 분기, 부모/아이 대사, 옛 저장 이어하기를 확인한다. 결과 PNG는 `production/qa/evidence/2026-11-11-slice-campaign-*.png`.
- 기존 화면 전수 79장과 능력 재검증 11장을 촬영했다. 능력 세 줄·기물 검사·빌드 화면도 회귀 검사를 수행했다. 전수 도구의 첫 능력 검사는 로딩 완료 전 입력으로 시간 초과를 냈다. `#boot` 종료 대기를 추가하고 같은 능력 시나리오를 DPR 1/2.625에서 재검증했다.
- 컷신 본문은 기존 두 줄·한 줄 30자 폭 예산으로 검사한다. 새 흉터 풀이가 카드 예산을 넘은 것은 짧게 수정했다. UI 검증은 글자/버튼 경계와 도트 이미지 비율·기기 픽셀 정수배를 포함한다.
- 주 실행 번들에서 옛 ‘열세 겹·승급 기록·정품 판정·또 아홉째’ 문구가 빠졌음을 확인했다. `legacy.html`의 옛 게임은 보관 구현이며 이번 새 본편의 기준이 아니다.

## 남은 그림 한 장

[S-01 아이와 부모의 손 — 독립 발주 프롬프트](../asset-order-master.md#s01-epilogue-hands). 실제 기물 생사와 무관한 동료를 그려 넣지 않도록 종이왕과 두 손만 요청했다. 운송은 상자 배경, 집의 부모·아이 대사는 종이왕만 있는 빈 무대로 재생한다. 공장 배경을 집으로 오인시키지 않는다. 아이의 손 원화가 이미 반입됐다고 보고하지 않는다. 수령 뒤 격자 복원·픽셀화·반입·컷 연결을 개발 측에서 수행한다.

APK 생성·공개 웹 아티팩트 배포·실제 기기/사용자 이해도 실험은 이번 작업에 포함하지 않았다. 문학적 최종 완성이나 모든 외부 원화의 재제작 완료를 주장하는 보고가 아니다.

현재 화면의 브라우저 UX는 위 검사 범위에서 **APPROVED**다. 부모·아이 원화 S-01과 실제 기기/사용자 이해도는 **NOT ASSESSED**이며 미완료로 구별한다.
