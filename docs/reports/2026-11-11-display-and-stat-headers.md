# 대표 화면 네 규격과 능력치 헤더 — D-429

PC 1280×720에서 보드가 작았던 원인은 기기별 지원 범위 자체보다, 터치 54px/PC 56px 칸 상한과 20도트 정수 내림이었다. 대표 규격과 보드 목표를 `src/data/display.ts`로 모으고 PC·태블릿의 칸 목표를 80px로 올렸다. 중간 크기는 같은 배치에서 맞추며, 740×360 같은 낮은 화면을 별도 기본 검수 대상으로 늘리지 않는다.

| 대표 화면 | CSS 크기 | 일반 6×6 판 실측 |
|---|---|---|
| 작은 모바일 | 667×375 | 칸50 / 보드300px |
| 모바일 | 915×412 | 칸50 / 보드300px |
| 태블릿 | 1024×768 | 칸80 / 보드480px |
| PC | 1280×720 | 칸80 / 보드480px (이전 칸40 / 보드240px) |

실제 판의 행·열과 남은 높이에 맞춰 칸 크기를 제한하므로 목표와 실측은 다를 수 있다. [브라우저 실측](2026-11-11-display-and-stat-headers.json). 검수 명령은 `OBSERVE_PRESET=small-mobile|mobile|tablet|pc CHROMIUM_PATH=/usr/bin/chromium node tools/slice-observe.cjs unit-info`.

## 능력치 정보

체력·방열판·공격력·방어력 이름을 원본 아이콘 오른쪽 상단 테에 배치했다. 아래 수치는 네 칸 모두 왼쪽 정렬이다. 원본 그림을 분해하거나 파일을 수정하지 않았다. 이름 바탕을 본체의 어두운 색과 맞춰 검은 돌출부 주변을 정보 헤더로 쓴다.

[모바일](../../tools/artguide/shots/unit-info-large.png) / [작은 모바일](../../tools/artguide/shots/unit-info-large-667x375.png) / [태블릿](../../tools/artguide/shots/unit-info-large-1024x768.png) / [PC](../../tools/artguide/shots/unit-info-large-1280x720.png) / [PC 대국](../../tools/artguide/shots/battle-pc.png).

규칙은 바꾸지 않았다. 일반 공격은 방어력으로 피해를 줄인 뒤, 남은 피해를 방열판이 흡수한다. 방어력은 타격마다 적용되고 소모되지 않으며, 방열판은 흡수한 만큼 소모된다. 공격20·방어력5·방열판10이면 피해15 중 방열판10이 사라지고 체력5가 줄어든다. 최소 피해와 기믹 피해의 예외는 기존 엔진 규칙을 따른다.

## 검증 범위

- 네 대표 규격에서 실제 기물 탭: 일반 기물·반장·큰 수치 12345/18000, 방열판87, 공격234, 방어18 확인. 글·수치 경계, 정보판 높이/화면 경계, 턴 종료 비가림, 바깥 탭 닫기 통과. 원본 프레임 파일 로드 검사 통과. 실제 화면 직접 대조.
- 기물 정보 UI audit: TXT/ERR 0개. 웹 빌드·34파일265개 로직 테스트 통과.
- PC 앱의 정수 확대 내림도 제거했다. 기본 모바일 915×412에 맞춰 1280 창에서 약1.399배로 UI 전체를 확대한다. resize/load 콜백에서 1280·1920 확대값 계산은 모의 Electron으로 검증했다. **네이티브 Electron 실행 화면은 NOT ASSESSED**: 환경에 실행 바이너리와 X 서버가 없다. 브라우저 PC 실화면 검증과 구분한다.
- UX: 이번 수정의 정보 위계·명칭·왼쪽 정렬·테두리·큰 수치·원본 보존·닫기 조작은 확인했다. 전체 게임의 접근성/노치/회전/모든 터치 최소 크기는 이번 검증 범위 밖으로 NOT ASSESSED.

새 발주·APK·웹 아티팩트 배포 없음. 그래픽 정본용 목록과 화면은 로컬 갱신했다.
