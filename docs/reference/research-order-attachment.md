# 조사 발주서 A — 유닛 애착: 플레이어는 왜 "말 한 개"를 잃고 아파하는가

> 발주: 2026-11-01 · 수행: 제미나이 서칭 프로젝트 · 근거로 쓸 곳: 상업성 진단 2번(기물 이름·성격·흉터)

## 목적
「Pawnisher : Checkmate」는 체스 기물로 분대를 꾸리고, HP가 다음 판으로 이어지며, 쓰러진 기물은 영영 빠진다. 지금은 기물이 그냥 "폰"이라 잃어도 아프지 않다. 같은 시스템 위에 **감정(애착·상실·자랑)**을 얹는 방법을 사례와 근거로 정리해 달라.

## 대상 게임
- 필수: Darkest Dungeon (1·2), XCOM 2, Into the Breach, Battle Brothers, FTL, Fire Emblem (클래식 모드), Wildfrost, Monster Train
- 선택: Rimworld, Dwarf Fortress, Banner Saga, Stoneshard, Inscryption(카드 인격화), Peglin, Loop Hero

## 조사 항목
1. **이름과 개성**
   - 유닛에게 이름·초상·성격·버릇을 주는 방식. 무작위 생성 vs 손으로 쓴 캐릭터.
   - 최소한의 정보(이름 하나, 대사 한 줄)로 애착이 생기는 사례. 텍스트 분량의 하한.
   - 플레이어가 직접 이름을 붙이는 기능의 효과 (XCOM의 친구 이름 붙이기 등).
2. **흔적과 성장 — "이 녀석은 나와 함께 왔다"**
   - 흉터, 버릇(quirk), 트라우마, 훈장, 처치 수 기록, 별명이 붙는 조건.
   - 성장이 유닛을 "대체 불가능하게" 만드는 구조 (레벨, 고유 기술, 장비 귀속).
   - 부정적 흔적(공포, 부상, 광기)이 오히려 애착을 키우는 사례와 근거.
3. **상실의 연출**
   - 영구 사망의 순간 연출: 화면, 소리, 문구, 묘비·추모 기록 (Darkest Dungeon 묘지, XCOM 추모비).
   - 잃은 유닛을 되살리는 장치가 있는 게임과 없는 게임의 차이 — 긴장감 vs 좌절감.
   - "아깝다 → 다시 한다"로 이어지게 하는 상실 설계 vs "그만둔다"로 끝나는 상실 설계 (리뷰 근거).
4. **유닛 사이의 관계**
   - 지원 대화, 동료 보너스, 라이벌 관계가 전술 선택에 주는 영향 (Fire Emblem 지원, Darkest Dungeon 상호작용).
   - 관계가 시스템(보너스)과 이야기(대사) 중 무엇으로 체감되는가.
5. **세계관과 묶기**
   - 유닛의 정체성을 세계관에 붙이는 방법 (출신, 소속, 계급, 제조 번호 같은 설정).
   - 우리 세계관 참고: 공장에서 출하되는 체스 기물, 검수관, 불량 폐기, 나사·태엽 경제. 이 설정에 어울리는 애착 장치가 있는가 (선택 — 근거와 분리해 표시).
6. **분량과 비용**
   - 소규모 팀이 쓴 실제 텍스트 분량(이름 풀, 대사 수, 버릇 수)과 생성 방식. 인디 사례 위주.
7. **역효과**
   - 애착 장치가 귀찮음이나 관리 피로로 바뀐 사례 (리뷰·포럼 근거).

## 결과물 형식
1. 게임별 1쪽 요약표: 개성 장치 · 흔적/성장 · 상실 연출 · 관계 · 분량.
2. 공통 원리 10개 이하: 원리 한 줄 + 근거 게임 2개 이상 + 출처.
3. "체스 기물 분대에 옮긴다면?" 제안 5개 (선택 사항 — 근거와 분리해 표시).
4. 모든 주장에 출처 링크. 추측은 추측이라고 표시.
