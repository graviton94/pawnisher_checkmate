# 빌드 재미 검증 — 다음 개발과 그래픽 발주

2026-11-11 · D-419 · 설계 기준: [GDD 18장](../gdd/18_builds_synergy_and_crew.md)

## 1. 다음 결과물

**혼성·나이트·룩 세 빌드가 서로 다른 판단을 요구하는 첫막 검증판**을 먼저 만든다. 첫 단계의 성공은 카드 수나 전체 완주율이 아니라, 같은 전장에서 행동 순서·자원 사용·위험 감수가 달라지는 것이다.

이번 문서는 작업 순서와 발주 프롬프트의 납품이다. 아래 개발은 아직 수행하지 않았다. GDD 18장의 후보 수치는 검증용이며, 새 규칙을 전부 확정하거나 본편 장 수를 바꾸는 결정이 아니다.

## 2. 담당과 작업 순서

| 순서 | Codex가 할 일 | 결과물·완료 조건 | 그래픽 의존 |
|---|---|---|---|
| V1-1 | 맞물린 톱니·공성 걸쇠를 순수 전투 규칙으로 구현 | 실제 실행·미리보기·되감기에서 동일한 결과, 발동 주체·횟수·비용 확인 | 기존 아이콘으로 가능 |
| V1-2 | 혼성·나이트·룩 고정 조건 사례 구성 | 정상 작동·재료 부족·불리한 배치·동료 손실을 각각 확인 | 없음 |
| V1-3 | 첫막 플레이에 세 운영 연결 | 사용자가 선택 이유를 설명하고 다른 운영을 다시 시도할 수 있는지 관찰 | I-14A/B 수령 시 교체 |

| V3 | 동료 식별·기여 기록·맞댄 철판 구현 | 고참과 신병의 차이, 보호자의 실제 기여, 손실과 복구가 성립 | I-14C |

| V5 | 한 출하와 반장의 유혹 연결 | 실제 이력을 쓰는 짧은 장면·약속·왕좌 선택을 연결 | 현재 반장·장면 그림 우선 검토 |

사용자는 아래 프롬프트로 그래픽을 제작·발주하고, 검증판에서 재미와 가독성에 대한 실제 플레이 의견을 준다. Codex는 받은 원본의 크기·도트·색·여백을 점검하고 파생 이미지·코드 연결·실행 확인을 담당한다. 그래픽이 오기 전에도 V1-1~2를 진행할 수 있다.

## 3. 첫 버전의 설계 명세

### 3.1 세 빌드의 질문

| 빌드 | 판단 | 첫 버전 재료 | 관찰할 차이 |
|---|---|---|---|
| 혼성 | 누구를 먼저 움직여 다음 기회를 열까 | 맞물린 톱니+서로 다른 유형의 기본 명령 | 첫 둘이 처치하지 않아도 다른 동료의 수를 연다 |
| 나이트 | 첫 처치를 어디서 얻고 어디로 이어갈까 | 기존 편자·집게·기습·피의 질주를 단계별로 제공 | 처치 시동의 유무와 다음 착지에 따라 행동 수가 달라진다 |
| 룩 | 방열판을 남길까, 일격에 쓸까 | 공성 걸쇠+기본 비용 1/2 룩 명령+방열판 공급 | 무거운 공격을 고르면 방어를 소모하고 퇴로가 달라진다 |

첫 비교는 K/P/N/R처럼 같은 분대와 같은 적 배치를 사용하고, 빌드 재료만 바꾼다. 이후 실제 영입과 보상으로 해당 구성이 만들어지는지 V2에서 따로 확인한다. 고정 손패 시험의 성공을 획득 난도 검증으로 보고하지 않는다.

### 3.2 맞물린 톱니

- 한 턴에 서로 다른 유형의 영구 동료 둘이 적에게 각각 실제 HP 또는 방열판 피해를 주면 태엽 +1. 부품 전체에서 턴에 한 번.
- 유형은 대국 입장 시 고정. 임시 폰·복제·한 폰의 승격을 서로 다른 영구 동료로 세지 않는다.
- 현재 대국의 분대 대응표와 기물 ID를 사용한다. 표시용 세 자리 시리얼만으로 동일성을 판정하지 않는다.
- 빈 이동·자가 피해·아군 피해·자동 반사로 조건을 채우지 않는다. 어떤 명령과 기물의 행동이 원인인지 보존한다.
- 최대 태엽 5를 따른다. 상한에서 초과분은 버리며 발동을 다음 수로 이월하지 않는다. 다른 환급과 함께 발생한 실제 획득량을 보여 준다.
- 시험: 같은 유형 둘 / 다른 유형 둘 / 한 기물 재행동 / 임시 폰 / 승격 / 광역 / 상한 / 턴 초기화 / 되감기.

### 3.3 공성 걸쇠

- 기본 비용 2 이상인 룩 이동 명령이 유효 공격을 할 때 해당 룩의 방열판을 최대 12 소모한다. 소모한 만큼 주 대상 직접 피해에 더한다. 룩마다 턴에 한 번.
- 다듬기로 실제 비용이 1이 되어도 기본 비용 2인 명령은 해당한다. 기본 비용 1인 명령은 방열판을 보존한다.
- 별도 활성화 단추 없이 어떤 명령을 쓰는지로 선택한다. 공격 전 미리보기에 소모 뒤 방열판과 직접 피해를 함께 반영한다.
- 주 대상은 기존 엔진의 직접 공격 대상 결정 규칙을 따른다. 여럿이면 기존의 결정론적 처리 순서에서 첫 대상을 고른다. 새로 별도 표적을 탭하게 하지 않는다.
- 충돌·관통의 뒷 대상·반사에 소모분을 다시 더하지 않는다. 자동 추가 공격으로 재발동하지 않는다.
- 시험: 방열판 0/5/15 / 기본 비용과 다듬은 비용 / 빈 이동 / 관통·충돌 / 룩 둘 / 공격 후 반사 / 턴 초기화 / 되감기.

### 3.4 구현 위치와 확인

| 범위 | 주 대상 | 확인할 것 |
|---|---|---|
| 효과 데이터 | `src/slice/parts.ts` | 이름·조건·수치·등급 후보·필요 기물 |
| 전투 판정 | `src/slice/battle.ts` | 발동 주체·종류·순서·상한·미리보기·되감기 |
| 획득 | `src/slice/main.ts`, `cards.ts`, `src/data/unlocks.ts` | 꾸러미와 일반 보상·상점의 공급 차이. 가능하면 생성 로직을 순수 함수로 분리 |
| 기록 | `src/slice/crew.ts`, `save.ts` | 영구 개체 식별, 원인별 기여, 저장 이전·이후의 중복 방지 |
| 표시 | 기존 부품 카드·발동 연출·전투 기록 | 누가 어떤 조건을 채웠는지 판독 가능한가 |

규칙 구현 후 의미 있는 단위 테스트와 전체 필수 검사를 실행한다. 화면 작업 때는 `/game-ui-design`→`/run-and-observe`→`/ux-review` 절차로 915×412, DPR 2.625에서 탭 조작·가독성을 확인한다. 아직 구현 전이므로 이 문서의 화면 판정은 **NOT ASSESSED**다. 핵심 재미 구현 전 승률 튜닝은 하지 않는다(D-080).

## 5. 발주와 반입

복사할 프롬프트는 [발주서 정본의 I-14A~D](../asset-order-master.md#build-prototype-assets)에 있다. **한 상자 전체를 새 생성 작업에 한 번씩 붙여 넣는다. 첨부 없이 사용할 수 있다.** A/B가 우선이다. 실제 그림 생성은 이번 작업에 포함하지 않는다.

- 납품: 512×512 투명 PNG 각각 한 장. 원본 논리 격자는 32×32이며 정확히 16배 확대된 도트여야 한다.
- 원본 보관 후보: `build-res/order/I-14A-source.png` 등. 받은 원본은 보존한다.
- 게임용 후보: `public/ui/icons16/relayGear.png`, `siegeLatch.png`, `sharedPlate.png`, `relaySeal.png` — 각각 32×32.
- 작은 표시용: 같은 이름의 `@16.png` — 각각 16×16. 자동 축소만으로 끝내지 않고 실루엣·구멍이 뭉개지는지 점검한다. 크기를 늘려 왜곡하지 않는다.
- 기존 `icon_sheet_import.py`는 시트용이다. 이 단일 아이콘 규격을 그대로 지원한다고 가정하지 않고, 받아 본 이미지에 맞춰 단일 이미지 반입 또는 시트 조립 후 가져오기를 선택한다.
- 임시 대응: `relayGear`→`forkGear`, `siegeLatch`→`anvilPlate`, `sharedPlate`→`shieldWall`, `relaySeal`→`royalSeal`. 기능 시험용이며 최종 식별성 합격을 뜻하지 않는다.

### 납품 확인 기준

1. 네 실루엣이 각각 기어 둘 / 걸쇠 / 철판 둘 / 세 갈래 인장으로 구분된다.
2. 실제 알파 투명이며 체크무늬나 배경색이 그림에 인쇄되어 있지 않다.
3. 32×32 격자로 정확히 돌아가고 가장자리에 반 도트·블러·글로가 없다.
4. 지정 팔레트와 1도트 외곽선, 왼쪽 위 광원이 유지된다. 금속 질감은 큰 단색 면으로 읽힌다.
5. 32×32와 16×16, 실제 카드와 부품 띠에서 식별할 수 있다. 희귀도·발동 여부를 원화에 굽지 않는다.

## 6. 첫 검증의 판정과 다음 행동

| 관찰 | 다음 보완 |
|---|---|
| 세 빌드의 최선 수가 거의 같다 | 더 많은 부품을 넣기 전에 조건·비용·표적의 차이를 보완 |
| 조합은 재미있지만 원하는 재료를 볼 기회가 없다 | V2 획득 경로·대체재·해금 풀 점검 |
| 좋은 조합이 매번 자동 완성된다 | 초기 꾸러미의 완성품 공급과 위험/돈/칸의 기회비용 점검 |
| 주력만 기억하고 조력자는 기억하지 못한다 | V3 실제 보호·길 열기 기여와 그 원인을 확인 |
| 전투가 재미있지만 왕좌의 선택이 무덤덤하다 | V5 실제 살아 있는 동료의 약속과 힘의 유혹을 장면으로 보완 |

첫 검증 완료 보고에는 기능 검사, 실제 화면 확인, 사용자 플레이 관찰을 구분해 남긴다. 자동 검사만으로 재미를 통과 처리하지 않는다.
