# 디자인 문법 정본 — 「주물 공방 문법」 (D-259)

> 사용자 (2026-11-06): 「전투 씬 FX나 대화창, 안내창, 팝업창 등도 어떤 건 잘 만들고, 어떤 건 엉망으로 만들고. 디자인 철학 제대로 안 세울래?」
> 원인: 원칙(D-216 도트만 · D-213 글씨 · D-180 박자)은 있었지만 **「무엇으로 만드는가」(재질 · 빛 · 부품)** 가 없었다. 화면마다 손으로 새로 그려서 같은 게임 안에서 문법이 달랐다.
> 이 문서는 모든 화면 요소가 따르는 하나의 문법이다. 새 화면 · 효과 · 팝업은 여기 부품을 조합해서만 만든다. 어기는 것은 고칠 목록에 올린다.

## 0. 한 문장
**작업대 위의 물건만 있다.** 화면의 모든 것은 공장에 실제로 있을 법한 쇠 · 황동 · 나무 · 종이 물건이고, 같은 빛(왼쪽 위)을 받고, 같은 손(코드 부품)이 찍는다. 떠다니는 글자 · 납작한 색 상자 · 출처 없는 빛은 없다.

## 1. 세 층 — 층마다 그리는 법이 하나
| 층 | 무엇 | 도트 | 그리는 법 |
|---|---|---|---|
| **장면** | 받은 장면 그림 · 판 · 기물 · 사건 장치 · 소품 | 3px (판 위는 판 격자) | 도트 캔버스 + `view/pxkit` 재질. 받은 그림(장면 · 초상)은 격자만 맞춘다 |
| **장치** | 패널 · 명패 · 단추 · 칸 · 테이프 · 판결 명패 | 2px (`--px`) | UI 크롬 9-slice(`assets/ui/chrome`) + 갈무리. 결과 알림은 `verdict()` |
| **빛** | 불꽃 · 불씨 · 연기 · 빛살 · 번쩍 | 장면과 같은 3px | `view/pxfx` 입자 · 빛만 (더하기 빛 · 연기 반투명은 이 층에서만 — D-249) |

- **섞지 않는다.** CSS 상자가 장면 속 물건인 척하지 않는다(예: 예전 「합격」 도장 = HTML 테두리 상자 → 금지). 캔버스가 패널 · 단추를 흉내 내지 않는다.
- 한 층 안에서는 도트 크기가 하나다. 아이콘 · 기호는 그 층의 도트에 정수 배율로만 올린다.

## 2. 재질 다섯 — 뜻이 정해져 있다
| 재질 | 램프 (`pxkit.M`) | 뜻 | 쓰는 곳 |
|---|---|---|---|
| **철** | iron | 구조 · 틀 · 중립 | 패널, 기계 몸통, 판, 리벳 |
| **황동** | brass | 손댈 수 있는 것 · 보상 · 이름 | 단추 · 명패 · 깔때기 · 자물쇠 · 좋은 판결 |
| **쇳물** | molten | 위험 · 힘 · 열 | 불, 경고 불빛, 공격 |
| **종이** | paper | 글 · 기록 · 주인공(종이 왕관) | 손짓 테이프 · 서류 · 카드 글 |
| **녹** | rust | 쇠락 · 손해 | 녹슨 카드 · 봉인판 녹 · 나쁜 판결의 얼룩 |
| (신호) 청록 / 진홍 | teal / crimson | 내 편 · 합격 / 적 · 불량 | 등불의 **빛**으로만 (물건의 몸 색으로 쓰지 않는다) |

## 3. 빛 공식 — 모든 물건이 같은 빛을 받는다
1. 1도트 먹 테(`#0b0b0e`)
2. 위 가장자리 = 램프 +2단, 왼 가장자리 = +1단 (빛은 왼쪽 위)
3. 몸 = 램프 가운데(3단)
4. 아래 · 오른 가장자리 = −1단
5. 바닥에 먹 그림자 1~3도트 (오른아래, 반투명 없음)
6. 부피가 있는 물건(기계 · 상자)은 **3/4 시점**: 위 면(밝게) + 앞 면 — `box3()`
7. 중간 톤은 같은 램프 이웃 단끼리 4×4 베이어 디더로만 (그라데이션 금지)
8. 유리 = 어두운 안 + 대각 반사 두 줄(디더), 등불 = 둥근 유리 + 흰 반사 한 점 — `lamp()`

## 4. 부품 — 이것만 조합한다
| 부품 | 코드 | 규칙 |
|---|---|---|
| 철판 패널 | `.panel9` (chrome/panel) | 모든 창 · 팝업 · 안내창의 몸 |
| 황동 명패 | `.plate` (chrome/plate) | 창 이름은 패널 위 가장자리에 걸친 명패 하나 |
| 움푹 칸 | `.inset` | 목록 · 기록 · 대사 칸 |
| 단추 | `.btn` 철 · 황동 · 진홍 · 청록 | 동사 하나. 황동 = 진행, 진홍 = 되돌릴 수 없음, 철 = 보조 |
| 손짓 테이프 | `.ev-tap` · `.mg-hint` (chrome/tape) | 「▼ 무엇을 한다」 — 종이 테이프, 계단으로 살짝 들썩 |
| 결과 줄 | `evstage.ts` `.ev-res` | 실제 카드 얼굴 · 기물 + HP 바에 FX — 아래 5장 |
| 재질 덩어리 | `block()` · `box3()` · `rivet()` · `lamp()` | 장면 속 물건은 모두 이걸로 |
| 도트 글씨 | `pixelText()` | 장면 속 글(새김 · 표지)은 갈무리를 문턱으로 잘라 단색 도트로 |

## 5. 결과 알림 — 실제 그림에 FX, 말은 대사가 (D-260)
- 결과를 따로 알리는 도장 · 명패를 띄우지 않는다. **바뀐 것 자체**(실제 카드 얼굴 · 실제 기물 그림 + HP 바)를 장면 위에 세우고 그 위에 FX를 얹는다. 무엇이 일어났는지는 대사(서술 · NPC)가 말한다.
- 카드: 강화 = 떨림 → 흰 번쩍 → 다듬은 카드 · 초록 불꽃 / 녹 = 잿빛 · 녹빛 3계단 / 파괴 = 잿빛 → 금 → 쇳조각 · 디더 퇴장 / 새 카드 = 디더 등장.
- 기물: 피해 = 붉은 번쩍 + HP 채움이 줄고 흰 잔상이 계단으로 따라옴(전투와 같다) / 회복 = 초록 계단 / 진화 = 흰 번쩍 → 새 기물 · 착지 출렁 / 썰림 = 베기 선 → 두 쪽 → 잿빛 · 디더 퇴장.
- `verdict()` 판결 명패(D-259)는 사건에서 뺐다. 다른 화면에 쓸지는 그 화면을 고칠 때 정한다.
- **박자 (D-398)**: 예비(떨림 · 번쩍 · 덜컹) → 터짐(계단 고리 3단 · `pxfx` 불똥 · **도트 낱말** — 전투 피해 숫자와 같은 `drawPopup`, 2배 → 1배 계단 튐 · 머묾 · 아래부터 디더 지움) → 출렁(`erLand`). 잃는 결과만 무대가 흔들린다. 낱말 색 = 전투 숫자 약속(얻음 금 · 회복 초록 · 잃음 진홍 · 녹 녹빛). 글 도장 · 꼬리표로 결과를 알리지 않는다.
- 나사 = 지갑 그림(날아들거나 쏟아짐), 부품을 고르게 됨 = 부품 상자(뚜껑 계단 열림). 독백 한 줄(‘ ’)은 무대 아래 단추 줄 왼쪽 움푹 칸.
- 장면 그림이 칸 끝에서 끊기지 않게 네 변 24도트를 Bayer 먹 점 가면으로 녹인다(`dither-edge-*`).

## 6. 확률 장치 — 사각 칸만 (D-260)
- 흐름: 대화창 + 선택지 → 고르면 오버레이에서 연출(동전은 저절로, 칸은 하나씩 눌러 · 긁어 연다) → 결과 + [확인] → 대화창에서 NPC 마무리 대사 + 나가기.
- 기계 · 상자 · 소품을 그리지 않는다. 확률이 걸린 사건은 장면(컷씬) 위에 **동전 하나** 또는 **움푹한 칸 셋**만 올린다: 동전 던지기 · 칸에 기호가 하나씩 떨어짐 · 칸을 덮은 녹을 손가락으로 긁음.
- 애태움(앞 둘이 같으면 셋째 칸 테가 깜빡)과 결과(칸 테 금 / 셋째 칸 붉음 + 불꽃 · 연기)는 예비 → 터짐 → 출렁임 박자.
- 장면 그림이 없는 사건은 공용 사건 배경 컷씬을 쓴다.

## 7. FX 문법 — 철학은 하나, 역할마다 다르게 (D-263)
| 역할 | 방법 | 금지 |
|---|---|---|
| 나타남 | 계단 프레임 + 디더 가면(`--px4 → --px0`, steps) | 투명도 보간 |
| 사라짐 | 디더 가면 퇴장(`pxOut` · `bfOut`) | 투명도 보간 · 흐려짐 가면 |
| 움직임 | 예비 동작 → 터짐 → 출렁임 (steps · 지수 곡선) | 선형 이동만 하는 슬라이드 |
| 불꽃 · 부스러기 · 연기 · 별 | `pxfx` 입자 (도트 그대로) | — |
| 응축 · 반짝임 · 열기 | `pxfx` 입자 + 빛 (도트화 최대한) | CSS 번짐 |
| 질감 · 무늬 | 단색 svg 도트 무늬 | 반투명 줄무늬 그라데이션 |
- JS의 `element.animate` 투명도 키프레임은 `fx3.ts`가 디더 가면으로 바꿔 돌린다 — 새 코드도 그대로 둔다.
- **빛 예외 (도트가 아니어도 받아들이는 곳 — 여기에만)**: ① `pxfx` 더하기 빛 (반장 등장 경계 · 반장 판 FX · 사건 오버레이 · 타격 번쩍) ② 승리 KO 빛살 `.ko3 .rays` ③ 타이틀 빛살 `.tfx-rays` ④ 조우 · 반장 등장 빛살 `.enc-rays` ⑤ 오프닝 안개 `.op-fog` ⑥ 되감기 화면 `.tapefx`(screen 합성, 무늬는 도트). 이 밖에 그라데이션 · 번짐은 쓰지 않는다.

## 능력 설명 문법 — D-422

능력 설명은 표시 장소와 관계없이 **명칭 / 조건·행동 / : 상세 효과** 세 줄을 쓴다.

```text
[검수]
2턴마다 최강 동료에 도장
: 해당 동료 공격 ×0.5
```

이름은 강조색, 행동은 본문, 상세 효과는 굵은 수치 문장으로 구별한다. 능력 하나를 장문 단락으로 합치지 않는다. 문장이 길면 뜻을 유지해 줄이며, 줄바꿈·말줄임·잘라내기·임의 글자 축소로 해결하지 않는다. 여러 능력이 있는 기물은 `1/2 · 다음`으로 같은 위치의 세 줄 카드를 넘긴다. 카드 본문의 분위기 문장과 실제 능력 규칙은 구별한다.

기물 검사표, 반장 규칙창, 빌드 부품 상세는 `src/data/ability-text.ts`와 `src/slice/ability.ts`를 공용한다. 새 능력도 여기에서 명칭·행동·효과를 먼저 나눈다. 원화에는 능력 문구·숫자를 굽지 않는다.


### 출하 끝과 사건 정보의 역할 (D-424·D-425)
- 출하 크레딧: 기존 크레딧 배경 + 먹 바탕의 이름/역할. 기물 사진 줄·중앙 철판 팝업을 쓰지 않는다. 모바일은 여섯 이름씩 넘기며 마지막은 제작진 두 역할이다. 출하 수치·해금·다음 회차는 이어지는 장부가 담당한다.
- 왕의 몸 결정: 기존 도금왕 그림을 화면 왼쪽에 크게, 오른쪽에 제목·증언·속말·결정. 첫 두 장은 동료 돌아보기/왕위 계승, 셋째 장은 왕위 계승/함께 출하의 유효한 두 선택이다. 740px 이하에서는 그림 42%/글 58%, 넓은 화면은 52%/48%. 그림의 비율은 유지한다. 버튼과 상태 반응은 기존 도트 키트를 쓴다.
- NPC 대사와 규칙 설명은 다른 자리다. 사건 정보 버튼은 왼쪽 효과 쪽지를 열고, 오른쪽 대사를 대체하지 않는다. 닫기·다음 설명으로 조작하며 선택 버튼과 정보 버튼은 별도 요소다.
- 선택지·결과 요약: 이득 `#b6edc0`, 손실 `#ffc0c0`, 수치 Galmuri11 12px/700. 회색 선택 판 `#56545e` 대비 각각 5.61:1/4.80:1. 종이 결과 쪽지는 이득 `#24603b`/손실 `#962f37`로 6.39:1/6.52:1. 부호·효과 동사도 남겨 색에만 의존하지 않는다. 전투·결과 FX의 기존 재질/숫자색과 구별한다.
- 전체 장면에서는 배경 입력을 격리하고 Tab 초점을 장면 안에 유지한다. 이동 줄이기에서 계단 등장·흔들림을 생략한다. 자세한 검사 결과는 [D-424 보고](reports/2026-11-11-end-scenes.md).

현재 이야기와 모드의 화면 문구는 [D-425 정본](brief/scenario-runtime.md)을 따른다. 정품 판정·13겹·거절 실패를 본편 진행 표시로 되살리지 않는다.


## 수령 원화 전체 보존 (D-428)

수령 원본은 전체 프레임을 픽셀화한다. UI-32 시트의 네 칸만 나누고, 칸 안의 하트·방열판·칼·방패와 UI-33 금색 핀은 원래 위치·색·윤곽 그대로 둔다. 상징·핀 독립 추출, 모서리 복제, 임의 팔레트 치환, 재조립은 하지 않는다. 9-slice는 장식이 들어 있는 모서리를 고정하고 빈 테만 늘린다. 원본과 실제 크기 화면을 함께 대조한다. 재생성 일치는 시각 품질 판정을 대신하지 않는다.

능력치 명판(D-429): 원본 아이콘 오른쪽의 상단 테에 체력·방열판·공격력·방어력을 올리고, 값은 그 아래 왼쪽 정렬한다. 이름의 바탕은 본체와 같은 어두운 재질로 두며 원본 파일을 수정하거나 상징을 분리하지 않는다.

손패 경첩(D-430): 전투 손패의 황동 경첩만 차콜 명암으로 바꿔 금색 비용 태엽과 분리한다. 원본 choice 프레임과 다른 선택지는 그대로 두고 hand-choice 파생본을 쓴다. 좌표·격자·알파 변경 없음. `tools/pixel/hand_choice.py`로 재현한다. 이를 UI 마감으로 두며 이후 작업은 빌드의 기능·획득 검증이다.

표시 이름(D-432): 긴 부품의 작은 카드 명패는 데이터의 `shortName`을 사용할 수 있다. 정식 `name`은 설명·접근성·기록에 보존한다. 동료 명패는 본명만, 자동 별명은 기존 받침 정보 줄에 표시한다. 임의 글자 축소·말줄임으로 이름을 맞추지 않는다. 개발용 카드 견본도 본편과 같은 카드 레일·배율을 사용한다.


부품 문법·높이(D-433): 모든 부품의 획득/상점 카드에서 묘사를 빼고 조건 → `: 효과` 순서의 세 행을 예약한다. 이름 명패와 그림 카드 비율은 기존 정본을 유지한다. 보유 부품 상세는 이름 / 조건 / `: 상세 효과` 세 줄이며 복합 판정은 다음 장으로 보존한다. 교체판은 같은 문법의 세 줄, 높이96px, 2열×2행 네 개씩 넘겨 본다. 페이지 이동 시 선택을 해제한다. 수량에 따라 글자/판 높이를 줄이거나 말줄임하지 않는다. 페이지 단추는 기존 철 단추 에셋을 재사용하며 별도 프레임 발주가 필요 없다.


받은 일러스트 공통 검수(D-441): UI 장치의 고정 광원·베이어 패턴 규칙을 모든 장면의 실제 광원에 강제하지 않는다. 사건·보스·서사 그림은 같은 재질/색면/제한적 디더링 언어를 공유하고 크기는 유형별 프로필을 따른다([ASSET-PROFILES.md](art/chatgpt-project/ASSET-PROFILES.md)). 반입의 격자 복원은 화풍 합격과 별개이며 현재 장면의 색 수는 자동 제한하지 않는다.
