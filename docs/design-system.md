# 디자인 문법 정본 — 「주물 공방 문법」 (D-259)

> 사용자 (2026-11-06): 「전투 씬 FX나 대화창, 안내창, 팝업창 등도 어떤 건 잘 만들고, 어떤 건 엉망으로 만들고. 디자인 철학 제대로 안 세울래?」
> 원인: 원칙(D-216 도트만 · D-213 글씨 · D-180 박자)은 있었지만 **「무엇으로 만드는가」(재질 · 빛 · 부품)** 가 없었다. 화면마다 손으로 새로 그려서 같은 게임 안에서 문법이 달랐다.
> 이 문서는 모든 화면 요소가 따르는 하나의 문법이다. 새 화면 · 효과 · 팝업은 여기 부품을 조합해서만 만든다. 어기는 것은 고칠 목록에 올린다.

## 0. 한 문장
**작업대 위의 물건만 있다.** 화면의 모든 것은 공장에 실제로 있을 법한 쇠 · 황동 · 나무 · 종이 물건이고, 같은 빛(왼쪽 위)을 받고, 같은 손(코드 부품)이 찍는다. 떠다니는 글자 · 납작한 색 상자 · 출처 없는 빛은 없다.

## 1. 세 층 — 층마다 그리는 법이 하나
| 층 | 무엇 | 도트 | 그리는 법 |
|---|---|---|---|
| **장면** | 받은 장면 그림 · 판 · 기물 · 사건 장치 · 소품 | 3px (판 위는 판 격자) | 도트 캔버스 + `view/pxkit` 재질. 받은 그림(장면 · 초상)은 격자만 맞춘다 |
| **장치** | 패널 · 명패 · 단추 · 칸 · 테이프 · 판결 명패 | 2px (`--px`) | UI 크롬 9-slice(`assets/ui/chrome`) + 갈무리. 결과 알림은 `verdict()` |
| **빛** | 불꽃 · 불씨 · 연기 · 빛살 · 번쩍 | 장면과 같은 3px | `view/pxfx` 입자 · 빛만 (더하기 빛 · 연기 반투명은 이 층에서만 — D-249) |

- **섞지 않는다.** CSS 상자가 장면 속 물건인 척하지 않는다(예: 예전 「합격」 도장 = HTML 테두리 상자 → 금지). 캔버스가 패널 · 단추를 흉내 내지 않는다.
- 한 층 안에서는 도트 크기가 하나다. 아이콘 · 기호는 그 층의 도트에 정수 배율로만 올린다.

## 2. 재질 다섯 — 뜻이 정해져 있다
| 재질 | 램프 (`pxkit.M`) | 뜻 | 쓰는 곳 |
|---|---|---|---|
| **철** | iron | 구조 · 틀 · 중립 | 패널, 기계 몸통, 판, 리벳 |
| **황동** | brass | 손댈 수 있는 것 · 보상 · 이름 | 단추 · 명패 · 깔때기 · 자물쇠 · 좋은 판결 |
| **쇳물** | molten | 위험 · 힘 · 열 | 불, 경고 불빛, 공격 |
| **종이** | paper | 글 · 기록 · 주인공(종이 왕관) | 손짓 테이프 · 서류 · 카드 글 |
| **녹** | rust | 쇠락 · 손해 | 녹슨 카드 · 봉인판 녹 · 나쁜 판결의 얼룩 |
| (신호) 청록 / 진홍 | teal / crimson | 내 편 · 합격 / 적 · 불량 | 등불의 **빛**으로만 (물건의 몸 색으로 쓰지 않는다) |

## 3. 빛 공식 — 모든 물건이 같은 빛을 받는다
1. 1도트 먹 테(`#0b0b0e`)
2. 위 가장자리 = 램프 +2단, 왼 가장자리 = +1단 (빛은 왼쪽 위)
3. 몸 = 램프 가운데(3단)
4. 아래 · 오른 가장자리 = −1단
5. 바닥에 먹 그림자 1~3도트 (오른아래, 반투명 없음)
6. 부피가 있는 물건(기계 · 상자)은 **3/4 시점**: 위 면(밝게) + 앞 면 — `box3()`
7. 중간 톤은 같은 램프 이웃 단끼리 4×4 베이어 디더로만 (그라데이션 금지)
8. 유리 = 어두운 안 + 대각 반사 두 줄(디더), 등불 = 둥근 유리 + 흰 반사 한 점 — `lamp()`

### 카드꼴은 모두 F 「용광로 액자」 가족 (D-583)
- 카드처럼 생긴 것 — 명령 · 부품 · 부적 · 손질 · 분대원 · 시작 세트 카드, 카드 받침, 손패 줄 — 은 한 가족이다: 84×126 도트 몸 · 테 → 홈 줄 → 안 · 핀 꽂은 종이 쪽지 · 등급 사다리(일반 맨 철 / 희귀 황동 덧쇠 · 머릿돌 · 청록 / 금 황동 · 쇳물 · 볏 · 불티, 등불 1 · 2 · 3, 움직임 없음 · 청록 띠 · 황동 띠 + 불꽃).
- 갈래는 **창 모양 · 창 속 장면 · 명판 모양**으로만 가른다(명령 화구 아치 · 부품 열린 해치 · 손질 작업대 구멍판 · 분대원 벽감 · 시작 세트 출하 상자). 새 카드꼴을 만들 때도 다른 틀을 만들지 않고 이 가족에서 창 · 명판만 고른다. 발주 29위 CD-01f · CD-06 ~ 11.

## 5. 결과 알림 — 실제 그림에 FX, 말은 대사가 (D-260)
- 결과를 따로 알리는 도장 · 명패를 띄우지 않는다. **바뀐 것 자체**(실제 카드 얼굴 · 실제 기물 그림 + HP 바)를 장면 위에 세우고 그 위에 FX를 얹는다. 무엇이 일어났는지는 대사(서술 · NPC)가 말한다.
- 카드: 강화 = 떨림 → 흰 번쩍 → 다듬은 카드 · 초록 불꽃 / 녹 = 잿빛 · 녹빛 3계단 / 파괴 = 잿빛 → 금 → 쇳조각 · 디더 퇴장 / 새 카드 = 디더 등장.
- 기물: 피해 = 붉은 번쩍 + HP 채움이 줄고 흰 잔상이 계단으로 따라옴(전투와 같다) / 회복 = 초록 계단 / 진화 = 흰 번쩍 → 새 기물 · 착지 출렁 / 썰림 = 베기 선 → 두 쪽 → 잿빛 · 디더 퇴장.
- `verdict()` 판결 명패(D-259)는 사건에서 뺐다. 다른 화면에 쓸지는 그 화면을 고칠 때 정한다.
- **박자 (D-398)**: 예비(떨림 · 번쩍 · 덜컹) → 터짐(계단 고리 3단 · `pxfx` 불똥 · **도트 낱말** — 전투 피해 숫자와 같은 `drawPopup`, 2배 → 1배 계단 튐 · 머묾 · 아래부터 디더 지움) → 출렁(`erLand`). 잃는 결과만 무대가 흔들린다. 낱말 색 = 전투 숫자 약속(얻음 금 · 회복 초록 · 잃음 진홍 · 녹 녹빛). 글 도장 · 꼬리표로 결과를 알리지 않는다.
- 나사 = 지갑 그림(날아들거나 쏟아짐), 부품을 고르게 됨 = 부품 상자(뚜껑 계단 열림). 독백 한 줄(‘ ’)은 무대 아래 단추 줄 왼쪽 움푹 칸.
- 장면 그림이 칸 끝에서 끊기지 않게 네 변 24도트를 Bayer 먹 점 가면으로 녹인다(`dither-edge-*`).

## 6. 확률 장치 — 사각 칸만 (D-260)
- 흐름: 대화창 + 선택지 → 고르면 오버레이에서 연출(동전은 저절로, 칸은 하나씩 눌러 · 긁어 연다) → 결과 + [확인] → 대화창에서 NPC 마무리 대사 + 나가기.
- 기계 · 상자 · 소품을 그리지 않는다. 확률이 걸린 사건은 장면(컷씬) 위에 **동전 하나** 또는 **움푹한 칸 셋**만 올린다: 동전 던지기 · 칸에 기호가 하나씩 떨어짐 · 칸을 덮은 녹을 손가락으로 긁음.
- 애태움(앞 둘이 같으면 셋째 칸 테가 깜빡)과 결과(칸 테 금 / 셋째 칸 붉음 + 불꽃 · 연기)는 예비 → 터짐 → 출렁임 박자.
- 장면 그림이 없는 사건은 공용 사건 배경 컷씬을 쓴다.

## 7. FX 문법 — 철학은 하나, 역할마다 다르게 (D-263)
| 역할 | 방법 | 금지 |
|---|---|---|
| 나타남 | 8×8 베이어 디더를 프레임마다 곡선으로(코드 64단 `ditherTo` · `pxIn`, CSS 16단 `--dq0 → --dq16`), 300 ~ 600ms (D-554) | 투명도 보간 · 다섯 단 이하 계단 |
| 사라짐 | 같은 디더 퇴장(`pxOut` 64단 · 최소 300ms, `bfOut` 16단) | 투명도 보간 · 흐려짐 가면 · 다섯 단 이하 계단 |
| 움직임 | 화면 프레임마다(60fps), 위치는 **기기 픽셀 정수**, 예비 동작 → 터짐 → 출렁임 곡선 (D-554) | 선형 등속 슬라이드 · 소수 위치(도트 번짐) · 낮은 프레임 계단 |
| 장면 전환 | 도트 칸 모양 — 디더 · 조리개 · 쇳물 · 철문 날 · 사선 · 블라인드 · 종이 쪽 · 바로(충격) (D-554) | 페이드 · 그라데이션 |
| 불꽃 · 부스러기 · 연기 · 별 | `pxfx` 입자 (도트 그대로) | — |
| 응축 · 반짝임 · 열기 | `pxfx` 입자 + 빛 (도트화 최대한) | CSS 번짐 |
| 질감 · 무늬 | 단색 svg 도트 무늬 | 반투명 줄무늬 그라데이션 |
- JS의 `element.animate` 투명도 키프레임은 `fx3.ts`가 디더 가면으로 바꿔 돌린다 — 새 코드도 그대로 둔다.
- **빛 예외 (도트가 아니어도 받아들이는 곳 — 여기에만)**: ① `pxfx` 더하기 빛 (반장 등장 경계 · 반장 판 FX · 사건 오버레이 · 타격 번쩍) ② 승리 KO 빛살 `.ko3 .rays` ③ 타이틀 빛살 `.tfx-rays` ④ 조우 · 반장 등장 빛살 `.enc-rays` ⑤ 오프닝 안개 `.op-fog` ⑥ 되감기 화면 `.tapefx`(screen 합성, 무늬는 도트). 이 밖에 그라데이션 · 번짐은 쓰지 않는다.

## 7.0 움직임 박자 — 부드러움은 프레임 수와 곡선에서 (D-554, D-216 · D-538을 고친다)
> 소유자 (2026-11-17): 「인트로 · 그림 바뀜 · 게임의 모든 전환이 뚝뚝 끊긴다. 장면 · 대사를 비주얼 노벨처럼 보여 주고 싶은데 그림이 너무 정적이다.」
> 원인: D-216 · D-538 뒤 움직임을 아주 적은 계단으로 바꿨다(컷신 카메라 한 장 90ms ≈ 11fps · 퇴장 3 ~ 5단 · 계단 키프레임). 도트는 지켰지만 프레임 수가 낮았다.
- **움직임**(카메라 이동 · 미끄러짐 · 배우 · 철문): 화면 프레임마다 돌리고 위치를 **기기 픽셀 정수**로 맞춘다 — 그림 도트 단위가 아니라 기기 픽셀 단위라 매끈하면서 도트가 번지지 않는다. 곡선은 늘 예비 → 터짐 → 출렁(`ease.abs`) · 감속(`ease.out` · `outExpo`) · 착지 넘침(`outBack`). 등속 직선 금지.
- **나타남 · 사라짐 · 전환**: 8×8 베이어 순서 디더를 프레임마다 곡선으로 넘긴다 — 코드는 64단, CSS 키프레임은 16단(`--dq0 ~ 16`, `tools/dither-css.cjs`가 펼침), 칸 = 게임 도트(`--px`). 300 ~ 600ms. 투명도 보간 · 그라데이션은 여전히 금지(D-216).
- **정지 동작은 일부러일 때만**: 도장 · 톱니 똑딱 · 흔들림 · 깜빡임 · 불똥 · 1도트 숨 고르기 · 등잔 깜빡. 이름 목록 = `src/data/motion.ts SMOOTH.hold`.
- **장치**: `src/view/motion.ts` — `tween`(프레임 시계) · `snapDev` · `ditherTo` · `bakeMotion`. CSS 키프레임 움직임은 시작 순간 120Hz 정수 행렬로 다시 굽고(`installSmoothMotion` — 옛 계단 키프레임도 곡선 위 표본으로 이어 매끈해진다), 코드 `element.animate`의 움직임도 같은 방법으로 굽는다(`fx3.installPixelAnimate` → `bakeWaapi`). 새 코드도 `transform` 키프레임을 그대로 쓰면 된다.
- **놀 때는 그리지 않는다 (D-533)**: 움직이는 동안만 프레임 시계가 돈다. 컷신 켄 번스는 한 줄이 서 있는 동안만(최대 7초), 같은 정수 위치면 쓰지 않는다.
- **박자 상한은 그대로**: 공격 1회 ≤ 1초(D-538 `FX_BUDGET`), 2단계 · 반장 등장 번쩍임 한 장(광과민 — 번쩍임 줄이기 설정), 움직임 줄이기면 끝 상태 하나.
- **컷신 = 비주얼 노벨 층** (`src/slice/vn.ts` · 데이터 `src/data/vn.ts`): 말하는 기물 도트가 정수배로 서고(들어옴 = 감속 + 디더), 말하는 배우만 밝게 · 나머지 50% 디더 그늘, 1도트 숨 고르기, 장면 입자(증기 · 불똥 · 먼지 · 재 · 불씨 — 켄 번스보다 1.6배 흘러 원근), 등잔 깜빡, 켄 번스, 대사 기록(백로그). 박자 약속: 충격 = 바로 · 시간 흐름 = 디더 · 한 곳에 모임 = 조리개 · 장소 바뀜 = 사선 · 닫힌 공간 = 철문 날 · 회상 = 종이 쪽.
- **측정**: `node tools/qa/framepace.cjs <intro|boss|screen|window|vn|all>` — 지켜볼 요소의 모습이 화면 프레임마다 바뀌는 비율 · 가장 오래 머문 프레임 · 정수 위치 비율과 실제 그려진 프레임 띠.

## 7.0a 프레임마다 vs 계단 — 무엇이 계단일 수 있나 (D-595, 7.0을 더 좁힌다)
> 사용자 실기기 (2026-11-19): 「화면 전환 · 희귀 카드 등장 등 화면 번쩍임이 그래픽 수준이 떨어지고, 희귀 이상 카드 빛이 지나가는 효과도 프레임이 너무 구림. 더 빠르게, 부드럽게. 픽셀아트라도 프레임 자체가 쓰레기 같은 건 용서 불가.」
- **「도트」 = 한 프레임이 또렷하고 위치가 기기 픽셀 정수에 붙는 것.** 낮은 프레임 수가 아니다. 움직임(위치 · 크기 · 쓸림)은 **화면 프레임마다**(60 · 고주사율이면 120) 곡선으로 — 작은 N의 `steps()`로 위치를 옮기는 것은 금지(일부러 정지 동작 `SMOOTH.hold`만 예외: 도장 · 톱니 똑딱 · 흔들림 · 깜빡).
- **계단이 되는 것은 둘뿐**: ① 디더 무늬 단계 — **12단 이상**(CSS `--dq`는 16단, 코드는 64단) ② 그림 줄(스프라이트) 장 넘김 — **장당 42ms 이하(24fps 이상)**. 불꽃 · 불티 · 귀퉁이 반짝은 장 넘김, 그 위치 · 띠의 이동은 프레임마다. 수치 = `src/data/motion.ts MOTION_CLOCK`.
- **움직임 시계는 하나**: 위치를 바꾸는 연출은 `tween`(rAF)이나 120Hz로 구운 Web Animations(`compTween` · `bakeMotion` · `installSmoothMotion` — 합성기에서 돌아 주 스레드가 바빠도 끊기지 않는다). `setTimeout`을 이어 붙여 장을 넘기지 않는다(시작 시각 잡기만 타이머).
- **칠하지 말고 옮긴다**: 움직이는 겹은 잘라 낸(가면 · overflow) 작은 겹 안에서 `transform`만 바꾼다. 큰 면의 `background-position` · `mask-image` · `box-shadow` · `filter` · 크기를 프레임마다 바꾸지 않는다 — 화면 전체 칠하기가 느린 폰에서 프레임을 먹었다(측정: 화면 전체 금빛 막 · 흰 막 · 등급 띠 8장 바꿈).
- **번쩍임 = 맞은 곳만, 장 수로 꺼짐**: 화면 전체 흰 · 금 막 금지. 맞은 곳 둘레 원형 디더(8×8 베이어, 칸 = 게임 도트, 가운데 최대 50%)가 **화면 3장**(50 → 22 → 6%)에 걸쳐 꺼진다 — `src/view/flash.ts impactFlash · flashAt`, 수치 `FLASH`. 번쩍임 줄이기 · 움직임 줄이기면 없다.
- **등급 빛 띠**: 이어 붙인 띠 하나(`tools/pixel/card_sweep.py`)가 쇠 테 가면(`.cf-sheen`) 안을 340ms 곡선으로 한 번 쓸고(정수 기기 픽셀 · 120Hz 구움, `src/slice/sheen.ts`), 금은 이어서 볏 불꽃 6장을 장당 40ms. 수치 `CARD_SHEEN`.
- **보이지 않는 것은 그리지 않는다**: 창(#overlay) · 반장 등장(`cover-fx`)이 판을 덮고 판 연출이 없으면 판 캔버스 그리기를 멈춘다(D-240 · D-533 연장) — 창 뒤에서 판이 초당 7 ~ 13장을 다시 그려 창 안 연출이 5fps로 떨어졌다.
- **측정**: `node tools/qa/motionpace.cjs <reveal|sweep|screen|boss|board|hit|all> --light` — CPU ×4 · 915×412 · DPR 2.625 · GPU 합성 길에서 평균 fps · 가장 긴 프레임 · 34/50ms 넘는 프레임 수(`--light` 없이 = 요소마다 프레임마다 바뀌나). 목표: 보이는 움직임 평균 55fps 이상 · 연출 중 50ms 넘는 프레임 없음.

## 카드 글 문법 — D-589 (사용자 결정: 「모든 카드 글을 한 문법으로」 — D-515 · D-511을 한 꼴로 묶는다)

카드 틀(`.cf`)로 나오는 성격은 여섯이다 — 명령(+ 다듬음 · − 녹) · 부품 · 부적 · 손질 · 분대원(기벽 · 이형 · 킹 · 흉터 · 영입) · 시작 세트. 고물상 · 전리품 · 덱 보기 · 분대 · 작업대 · 부품 고르기 · 영입 · 시작 세트 고르기 · 판 길게 누름이 모두 이 카드를 그대로 쓴다. 사건 선택지 · 기물 정보(능력 세 줄, D-422) · 손패 줄은 카드 틀이 아니다.

### 부관 띠 자리 규칙 (D-535)
전투 화면의 부관 띠(입문 시험대 A · B · C의 안내 띠 · 첫 판 코치 띠)는 `placeSubAway`(`src/slice/voice.ts`) 하나로 선다.
1. **짚은 곳 반대쪽 끝**: 그 걸음이 짚은 곳(안내 막의 구멍 · 코치가 지금 고르라는 칸)의 가운데가 판 열 아래 절반이면 판 열 위 끝, 위 절반이면 아래 끝. 짚은 곳이 없으면 내 킹 반대쪽.
2. **가리지 않는 것**: 안내 막의 모든 구멍(짚은 곳 + 보이기만 하는 구멍, 테 4px 포함) · 내 킹 칸 · [건너뛴다]. 코치는 단계별로 빛나는 기물 · 갈 칸 · 적(번호 딱지) · 붉은 칸 위 내 기물 · 턴 끝 단추 · 카드를 고를 때 손패와 적 킹. 겹침은 띠 몸 · 이름표 · 초상 홈 조각마다 잰다.
3. 바라는 끝이 막히면 반대 끝 → 두 끝 사이를 4px씩 훑어 가장 가까운 빈 자리, 가로는 판 열 가운데 → 화면 오른쪽 · 왼쪽 끝. 입문 안내는 빈 자리가 늘 있게 걸음의 짚을 곳을 고른다(판 전체를 구멍으로 두지 않는다 — 인사 · 맺음은 구멍 없이, 「적도 칩니다」 · 「빗나갔습니다」는 적 졸만). 코치 띠는 빈 자리가 없으면 그 단계만 접는다(판이 먼저, 원칙 7).
4. **글 두 줄**: 15px 갈무리14 그대로(D-213, 글자 축소 금지), 띠 폭 = 판 열(좁으면 456px까지 레일 위로) → 같은 줄 수를 지키는 가장 좁은 폭으로 맞춤(`fitSubWidth`). 넘치면 `docs/voice.md`대로 문구를 다듬는다. 다 찍힌 글로 높이를 먼저 잡아 찍히는 동안 띠가 자라지 않는다.
5. **[건너뛴다]는 띠 밖** 화면 왼쪽 아래 모서리 하나(덱 · 분대 자리 — 입문에서 짚지 않는 곳), ▼는 띠 아래 테 오른쪽. 띠가 어디에 서든 같은 자리(원칙 8).
6. **검증**: `node tools/qa/sweep.cjs [667] --only drill`의 `band-walk` — 입문 31걸음 + 코치 3턴을 실제 탭으로 넘기며 걸음마다 띠 조각이 구멍 · 내 킹과 겹치거나 두 줄을 넘으면 실패로 적는다.


### 발동 유형 문법 — D-592 (조건 칸 끝말이 유형을 말한다)
| 유형 | 조건 칸 ② | 효과 칸 ③ | 예 |
|---|---|---|---|
| 즉발 | 비움 | 효과만 | 철벽 「방열판 +15」 |
| 사건 | 「[턴에 한 번, ]<사건> 시」 | 효과 | 「턴에 한 번, 킹 피격 시 / : 다음 턴 태엽 +1」 |
| 상태 | 「<상태>면」 | 효과 | 「두 적 이상 치면 / : 피해 ×1.8」 |
| 지속 | 「<상태>인 동안」 | 효과 | 「킹 HP 30% 미만인 동안」 |
| 비례 | 「<수량> N당」 · 「잃은 HP만큼」 | 1당 값 | 「연쇄 1당 / : 피해 ×0.5 추가」 |
| 기록 | 「<기록> 기록 N당 / …면」 | 값 | 「처치 기록 1당 / : HP +2」 |
| 대가 | 비움 | **첫 항목 = 대가**(소모 · 바침 · 녹임) | 「연쇄 모두 소모 / 연쇄 1당 킹 방열판 +6 / 최대 24」 |
| 상시 | 「장착 중」(기벽은 비움) | 효과 · 대가는 「턴마다 · 대국마다 · 늘」 | 「장착 중 / : 공격 ×1.4 / 턴마다 킹 −4」 |
| 대상 | 맨 명사구 | 효과 | 「맞은 적 / : 다음 턴 행동 불가」 |
- 효과 한 항목에만 붙는 부분 조건도 같은 끝말: 「충돌 시 피해 30」 · 「처치당 카드 +1」 · 「처치했으면 태엽 0」. 「마다」는 턴 · 대국 되풀이에만, 「때」는 쓰지 않는다. 이득 · 손실에는 부호.
- **판 위 조건 표시**: 상태 · 비례 카드가 지금 맞으면 손패 줄에 황동 테 2px + 램프(`ui/part-state/ready.png`) + 까닭 한 줄 · 판은 조건 맞는 갈 칸에만 황동 L자 모서리(`ui/board/cond.png`) + 램프 · 기물 발치 램프 · 부품 칸 ready/waiting. 켜짐 계단 3프레임 + 번쩍 한 번, 꺼짐 2단 디더. 사건형 명령 카드는 램프 없음. 판정은 엔진 `cardCond` · `partCond` 하나(UI가 다시 짜지 않는다).

## 능력 설명 문법 — D-422

능력 설명은 표시 장소와 관계없이 **명칭 / 조건·행동 / : 상세 효과** 세 줄을 쓴다.

```text
[검수]
2턴마다 최강 동료에 도장
: 해당 동료 공격 ×0.5
```

이름은 강조색, 행동은 본문, 상세 효과는 굵은 수치 문장으로 구별한다. 능력 하나를 장문 단락으로 합치지 않는다. 문장이 길면 뜻을 유지해 줄이며, 줄바꿈·말줄임·잘라내기·임의 글자 축소로 해결하지 않는다. 여러 능력이 있는 기물은 `1/2 · 다음`으로 같은 위치의 세 줄 카드를 넘긴다. 카드 본문의 분위기 문장과 실제 능력 규칙은 구별한다.

기물 검사표, 반장 규칙창, 빌드 부품 상세는 `src/data/ability-text.ts`와 `src/slice/ability.ts`를 공용한다. 새 능력도 여기에서 명칭·행동·효과를 먼저 나눈다. 원화에는 능력 문구·숫자를 굽지 않는다.


### 출하 끝과 사건 정보의 역할 (D-424·D-425)
- 출하 크레딧: 기존 크레딧 배경 + 먹 바탕의 이름/역할. 기물 사진 줄·중앙 철판 팝업을 쓰지 않는다. 모바일은 여섯 이름씩 넘기며 마지막은 제작진 두 역할이다. 출하 수치·해금·다음 회차는 이어지는 장부가 담당한다.
- 왕의 몸 결정: 기존 도금왕 그림을 화면 왼쪽에 크게, 오른쪽에 제목·증언·속말·결정. 첫 두 장은 동료 돌아보기/왕위 계승, 셋째 장은 왕위 계승/함께 출하의 유효한 두 선택이다. 740px 이하에서는 그림 42%/글 58%, 넓은 화면은 52%/48%. 그림의 비율은 유지한다. 버튼과 상태 반응은 기존 도트 키트를 쓴다.
- NPC 대사와 규칙 설명은 다른 자리다. 사건 정보 버튼은 왼쪽 효과 쪽지를 열고, 오른쪽 대사를 대체하지 않는다. 닫기·다음 설명으로 조작하며 선택 버튼과 정보 버튼은 별도 요소다.
- 선택지·결과 요약: 이득 `#b6edc0`, 손실 `#ffc0c0`, 수치 Galmuri11 12px/700. 회색 선택 판 `#56545e` 대비 각각 5.61:1/4.80:1. 종이 결과 쪽지는 이득 `#24603b`/손실 `#962f37`로 6.39:1/6.52:1. 부호·효과 동사도 남겨 색에만 의존하지 않는다. 전투·결과 FX의 기존 재질/숫자색과 구별한다.
- 전체 장면에서는 배경 입력을 격리하고 Tab 초점을 장면 안에 유지한다. 이동 줄이기에서 계단 등장·흔들림을 생략한다. 자세한 검사 결과는 [D-424 보고](reports/2026-11-11-end-scenes.md).

현재 이야기와 모드의 화면 문구는 [D-425 정본](brief/scenario-runtime.md)을 따른다. 정품 판정·13겹·거절 실패를 본편 진행 표시로 되살리지 않는다.


## 수령 원화 전체 보존 (D-428)

수령 원본은 전체 프레임을 픽셀화한다. UI-32 시트의 네 칸만 나누고, 칸 안의 하트·방열판·칼·방패와 UI-33 금색 핀은 원래 위치·색·윤곽 그대로 둔다. 상징·핀 독립 추출, 모서리 복제, 임의 팔레트 치환, 재조립은 하지 않는다. 9-slice는 장식이 들어 있는 모서리를 고정하고 빈 테만 늘린다. 원본과 실제 크기 화면을 함께 대조한다. 재생성 일치는 시각 품질 판정을 대신하지 않는다.

능력치 명판(D-429): 원본 아이콘 오른쪽의 상단 테에 체력·방열판·공격력·방어력을 올리고, 값은 그 아래 왼쪽 정렬한다. 이름의 바탕은 본체와 같은 어두운 재질로 두며 원본 파일을 수정하거나 상징을 분리하지 않는다.

손패 경첩(D-430): 전투 손패의 황동 경첩만 차콜 명암으로 바꿔 금색 비용 태엽과 분리한다. 원본 choice 프레임과 다른 선택지는 그대로 두고 hand-choice 파생본을 쓴다. 좌표·격자·알파 변경 없음. `tools/pixel/hand_choice.py`로 재현한다. 이를 UI 마감으로 두며 이후 작업은 빌드의 기능·획득 검증이다.

표시 이름(D-432): 긴 부품의 작은 카드 명패는 데이터의 `shortName`을 사용할 수 있다. 정식 `name`은 설명·접근성·기록에 보존한다. 동료 명패는 본명만, 자동 별명은 기존 받침 정보 줄에 표시한다. 임의 글자 축소·말줄임으로 이름을 맞추지 않는다. 개발용 카드 견본도 본편과 같은 카드 레일·배율을 사용한다.


부품 문법·높이(D-433 — 묘사 칸은 D-589 · D-590으로 되살렸다: 설명지 ① 묘사 2행 + 아래 칸): 모든 부품의 획득/상점 카드에서 묘사를 빼고 조건 → `: 효과` 순서의 세 행을 예약한다. 이름 명패와 그림 카드 비율은 기존 정본을 유지한다. 보유 부품 상세는 이름 / 조건 / `: 상세 효과` 세 줄이며 복합 판정은 다음 장으로 보존한다. 교체판은 같은 문법의 세 줄, 높이96px, 2열×2행 네 개씩 넘겨 본다. 페이지 이동 시 선택을 해제한다. 수량에 따라 글자/판 높이를 줄이거나 말줄임하지 않는다. 페이지 단추는 기존 철 단추 에셋을 재사용하며 별도 프레임 발주가 필요 없다.


받은 일러스트 공통 검수(D-441): UI 장치의 고정 광원·베이어 패턴 규칙을 모든 장면의 실제 광원에 강제하지 않는다. 사건·보스·서사 그림은 같은 재질/색면/제한적 디더링 언어를 공유하고 크기는 유형별 프로필을 따른다([ASSET-PROFILES.md](art/chatgpt-project/ASSET-PROFILES.md)). 반입의 격자 복원은 화풍 합격과 별개이며 현재 장면의 색 수는 자동 제한하지 않는다.


장면 그림 채움(D-443): 프롤로그·격파·엔딩·크레딧·선택 화면·사건·상점·손질·막 소개의 일러스트는 **비율 유지 확대 후 크롭(cover)** 하나로 통일한다. 전체 화면 컷은 화면 전체, 분할 구성은 배정된 그림 영역 전체를 채운다. 기물·아이템·프레임에는 이 정책을 적용하지 않는다. 기기 픽셀 정수 배율과 지정 초점을 유지하고 빈 양옆을 장식으로 메우지 않는다. 원본 파일은 자르거나 변형하지 않는다. 반장 등장의 초상도 오른쪽 그림 영역을 같은 계산으로 채운다.

부품 상태(D-443): UI-34의16px 표식을 보유 부품 오른쪽 아래에 붙이며 상세에 한국어 상태·진행을 함께 쓴다. 대기는 소유만 하고 조건을 못 맞춘 상태, 가능은 현재 손패·태엽·합법 행동 중 실제 발동하는 행동이 있는 상태, 소진은 이번 턴 실행 기록이 있는 상태다. 여러 룩의 공성 걸쇠는 미사용 룩 수를 함께 표시한다. 애니메이션/적 차례에는 가능 상태를 예측하지 않는다.
