# UX Review (Pawnisher)

Claude Code Game Studios의 `/ux-review` 점검표를 우리 게임(모바일 가로 우선, HTML 오버레이 + Phaser 보드)에 맞게 줄이고,
ui-ux-pro-max의 모바일·게임 가이드로 기준값을 채웠다.

## 0. 근거 확보 (없으면 NOT ASSESSED)
- `/run-and-observe <화면>`으로 모바일(915×412) 스크린샷을 만든다. PC 레이아웃을 바꿨으면 `--pc`도.
- 스크린샷을 못 만들면 그 화면의 시각 항목은 전부 **NOT ASSESSED — 스크린샷 없음**.
- 세부 기준이 애매하면 검색: `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "<한 가지 결과>" --domain ux`
  (결과는 권고일 뿐, 이 문서·CLAUDE.md 원칙이 우선).

## 1. 점검표

### 터치 · 조작
- [ ] 모든 버튼/칩/카드 터치 영역 ≥ 48dp (CSS px), 인접 간격 ≥ 8px
- [ ] 보드 칸 ≥ 48dp, 탭 한 번으로 예약 확정, 되돌리기·초기화가 늘 같은 자리
- [ ] 호버로만 볼 수 있는 정보 없음 (모바일은 탭·길게 누르기 대안)
- [ ] 비활성 상태가 눈에 보임 (흐림 + 누르면 이유 토스트)

### 가독성 · 위계
- [ ] 본문 ≥ 14px, 보조 ≥ 12px, 대비 ≥ 4.5:1 (어두운 배경)
- [ ] 보드가 화면의 주인공. 레일 정보는 "지금 결정에 필요한 것"만
- [ ] 한 화면에 동시에 움직이는 강조 요소 1~2개
- [ ] 숫자(피해·배율·골드)는 아이콘/라벨과 함께, 단위가 분명

### 결과 미리보기 · 피드백 (이 게임의 핵심)
- [ ] 누르기 전에 결과가 보임: 이동 칸, 치는 칸(과녁), 처치(금색), HP 예측
- [ ] 숨은 규칙(이동한 기물만 공격, 체크 등)을 화면이 알려 준다 (안내 토스트·표시)
- [ ] 조작마다 즉시 반응 (선택 테두리·토스트), 적 차례에는 "적 차례" 상태 표시
- [ ] 연출 중 입력 잠금이 보이고, 공격 연출 1회 ≤ 0.6초

### 접근성
- [ ] 색만으로 구분하지 않음 (진영: 흰/검은 기물 + 받침 모양 / 위험: 색 + ☠·과녁)
- [ ] `prefers-reduced-motion`에서 흔들림·긴 트윈이 줄어든다
- [ ] 화면 회전 안내(세로일 때), 안전 영역(노치) 여백

### 상태
- [ ] 빈 상태(예약 없음, 카드 없음, 인챈트 없음)에 안내 문구
- [ ] 오류 상태(골드 부족, 덱 한도, 슬롯 가득) 메시지가 원인과 해결을 말함
- [ ] 저장·이어하기 후 같은 화면으로 돌아옴

## 2. 판정
- **APPROVED**: 모든 항목 확인, 문제 없음
- **NOT ASSESSED**: 하나 이상 확인 못 함 (어느 항목인지, 왜인지 적는다) — APPROVED보다 위, 수정 판정보다 아래
- **NEEDS REVISION**: 고칠 항목이 있음 (항목 · 스크린샷 경로 · 제안)
- **MAJOR REVISION NEEDED**: 핵심 흐름이 막히거나 정보 위계가 무너짐
