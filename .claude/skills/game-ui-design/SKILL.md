# Game UI Design (Pawnisher)

정본 지식: `docs/reference/game-ui-design.md` (이하 「지식 문서」). 재질 · 빛 · 부품은 `docs/design-system.md`, 말투는 `docs/voice.md`.
원칙: **취향으로 그리지 않는다.** 모든 크기 · 배치는 지식 문서의 수치에서 가져오고, 그림(틀 · 장식)은 발주한다(D-386).

## 0. 먼저 — 모달이 필요한가 (1분)
- 행동이 없는 정보 → 모달 금지. 토스트(지식 문서 4.6) · 판 위 표시 · 길게 누르기 정보(4.3).
- 흔하고 되돌릴 수 있는 행동 → 확인창 금지. 바로 하고 되돌리기를 같은 자리에(ITB).
- 남는 것: 결정 · 되돌릴 수 없는 드문 일 · 집중할 일만 모달.
- 가능하면 Game UI Database(https://www.gameuidatabase.com)에서 같은 종류 화면 5장을 사용자에게 링크로 제시하거나, 지식 문서 1장의 해당 게임 사례를 인용한다.

## 1. 분류 + 레시피 고르기
지식 문서 4장의 여섯 중 **하나만**: 확인(S) · 하나 고르기 보상(M/L) · 정보 · 엿보기(S→M) · 상점(L) · 대화 · 사건(L/M) · 토스트(모달 아님).
둘에 걸치면 화면을 둘로 나눈다(점진적 공개). 모달 안에 모달 금지.
적는다: `분류 = …, 크기 단계 = S 352 / M 592 / L 883, 레시피 = 4.x`.

## 2. 필요한 그림 목록 → 없으면 발주
- 레시피에 쓰이는 부품을 나열한다: 철판 창 · 황동 명패 · 단추(재질 · 상태) · 선택지 판 · 움푹 칸 · 꼬리표 · 액자 · 아이콘 · 장면 그림.
- `src/assets/ui/chrome/`(v2 포함) · `public/` 에 있는지 확인한다.
- **없으면 그리지 않는다.** 지식 문서 7장 표(U-01 ~ U-14)의 규격으로 `docs/asset-order-master.md`에 발주 상자를 쓴다(원본 크기 · 9-slice 테 · 상태 · 변 방식 · 첨부 · 놓일 경로). 받기 전에는 기존 부품을 빌려 쓰고, 「임시 — U-0x 대기」를 보고에 적는다.
- 받은 그림: 비율 유지(cover로 자르기, 초점 지정) · 정수배 · `image-rendering: pixelated` (지식 문서 3.6).

## 3. 수치 정하기 (그리기 전에 종이 계산)
- 폭: S 352 · M 592 · L min(883, 100vw−2G). 다른 값 금지. 안전 여백 G = max(16px, safe-area).
- 해부: 패널 테 10 · 안쪽 여백 12 · 명패 48 높이(위 테에 16 걸침) · 묶음 사이 16 · 묶음 안 8 · 단추 줄 48.
- **세로 예산 합을 적는다** — 높이 상한 364. 넘으면 ① 글을 줄이고 ② 선택지 수를 줄이고 ③ 화면을 나눈다. 스크롤 · 글자 축소 · 잘림 금지.
- 글: 제목 24 갈무리11 굵게(≤12자) · 본문 15 갈무리14(줄높이 1.5) · 보조 12 갈무리11 · 큰 수치 30 · 10 갈무리9는 카드 글 맞춤에만. 크기 3단 · 강조색 1개.
- 글 예산(지식 문서 4장): 확인 본문 ≤2줄 · 정보 ≤4줄(넘으면 넓힘) · 사건 서술 ≤2줄 · 대사 ≤2줄 · 선택지 = 이름 1줄(≤16자) + 결과 1줄(≤28자) × 최대 3 · 토스트 1줄 ≤20자.
- 단추: 가로 줄 최대 2개, 진행(황동) 오른쪽 · 취소/건너뛰기(철) 왼쪽, 같은 크기, 동사 ≤6자, 수치는 꼬리표로. 셋 이상은 세로 선택 블록.
- 닫기: 정보 · 확인 = 뒤 막 누르면 닫힘. 되돌릴 수 없는 선택 대기 창 = 뒤 막으로 안 닫힘. 위 모서리 X 금지.
- 움직임: 뒤 막 디더 3계단 · 창 m3in(예비 → 터짐 → 출렁임). 투명도 보간 · 선형 슬라이드 금지(D-216 · D-263).
- 이 숫자를 `src/data/` 또는 CSS 변수 하나에 모아 두고, 화면마다 `max-width`를 새로 짓지 않는다.

## 4. 찍고 점검 (915×412, DPR 2.625)
- `/run-and-observe`로 실제 화면을 탭해 연다. 스크린샷 → `production/qa/evidence/<날짜>-<화면>.png`.
- `node tools/artguide/ui-audit.cjs <폴더>` — `TXT` 줄(넘침 · 말줄임 · 허용 밖 크기) 0개.
- 지식 문서 **6장 점검표 13항목**을 원본 크기 스크린샷에 하나씩 적용하고 결과를 표로 남긴다(✓ / ✗ / NOT ASSESSED). 특히: 잘림 · 폭 단계 · 세로 ≤364 · 5초 테스트 · 단추 자리 · 테 두께 고른지(확대) · 그림 비율.
- ✗가 하나라도 있으면 3으로 돌아간다. 같은 ✗를 두 번 고치지 못하면 원인(부품이 없음 → 2의 발주)을 적는다.
