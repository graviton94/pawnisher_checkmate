# Balance Check (D-385)

## 도구 — 둘을 섞지 않는다 (사용자 결정)
- **퀵 등반 머신** `npm run climb -- --styles search,greedy,naive,random --asc 0,4,8,13 --n 50 --jobs 4`
  화면 없이 `src/sim/runbot.ts`(실제 대국 엔진 + 봇)로 출하를 돌리고 **표 한 장만** 찍는다 — 토큰 · 세션 절약. 원자료가 필요하면 `--out sim/climb-<날짜>.json`.
  50판 × 조합 4개 ≈ 2분(4코어). 결과 표를 그대로 보고에 붙인다(로그를 읽지 않는다).
- **화면 리뷰** `npm run review -- <폴더>` (프리뷰 서버 4173이 떠 있어야 함): 실제 단추를 누르며 한 판을 끝까지 — 멈춤 · 오류 · 깨진 화면만 본다. 밸런스 수치는 재지 않는다.
- 아이템 힘 값 · 짝 비교는 `sim/relic.sim.ts`, 부품 칸 점검은 `sim/slots.sim.ts`.

## 목표 띠 (D-542 — 눈금 = 두뇌 봇. 옛 D-316 · D-382의 「보통 봇 35~40%」는 버렸다)
두뇌 봇(search) = 예고를 다 읽는 꼼꼼한 사람(되감기 · 마지막 한 수 같은 사람 보험 없이). 사람은 보험만큼 이 표보다 5~10%p 쉽다고 본다.
왕관 n = 승급 n−1(0~3) · 도전 n = 승급 n+3(4~13). **첫째 왕관은 첫 출하로 잰다**: `--asc 0 --pools starter`(처음 풀 · 여벌 심장 1 · 1막 반장 안전망 — `simulateRun`의 first). 나머지는 `--pools all`.

| 봇 \ 출하 | 첫째 | 둘째 | 셋째 | 넷째 | 도전 1 | 도전 5 | 도전 10 |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 두뇌 (search) | **70~80** (여벌 심장 있는 첫 출하 기준) | 55~65 | 45~55 | **35~45** | 30~40 | 20~30 | **10~20** |
| 보통 (greedy) | 12~22 | 5~12 | 2~8 | 0~5 | ~0 | 0 | 0 |
| 단순 (naive) | ≤ 5 | 0 | | | | | |
| 무뇌 (random) | 0 · 90% 넘게 1막에서 끝 | 0 | | | | | |

- 계단: 한 단계 −5~12%p, **−15%p 넘으면 절벽**. 도전 1은 넷째 왕관보다 어려워야 한다.
- 위험 지표(두뇌): 킹이 HP 50% 아래로 내려간 대국 **15~25%** · 출하의 85% 이상이 한 번은 겪음.
- 반장별 승(두뇌): **85~95%**.
- 손 놓은 턴(태엽이 남고 낼 카드가 있는데 끝낸 턴)은 봇 실수가 아니라 측정 오차다 — 높으면 봇부터 고친다.
- 표본: 왕관 1~4는 150판(±5%p), 도전은 60판(±12%p). 50판 표본은 ±13%p — 차이가 그보다 작으면 판정하지 않는다.
- 킹 위험 지표는 계측판으로 잰다(`docs/reports/2026-11-17-difficulty-pass.md` 재현 절). 반장 승은 climb 표의 「반장승%」.
